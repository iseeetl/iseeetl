# v1 APIトークンの発行

環境管理者が、指定したユーザのv1 API用トークンを発行する手順です。

## 準備

- 対象バージョンのソースコードを取得してください。このCLIは配布アーカイブには含まれません。
- リポジトリルートで実行します。Node.jsとバックエンドの依存パッケージは[ローカル開発の準備](../../testing/local-development.md)に従って用意してください。
- 対象環境のバックエンドと同じ`JWT_DEV_SECRET`を設定した環境ファイルを用意します。フロントエンド用の環境ファイルは使用しません。
- 対象ユーザのID（24桁の16進文字列）を確認します。ユーザは未削除で、現在のロールが`developer`である必要があります。

通常のユーザ登録後に[ユーザ管理](../management/user-management.md)で「開発者」へ変更できます。管理者の`Administrator`はv1用のロールとは異なります。対象フロア・ルームへのアクセス権も確認してください。

## 発行する

環境ファイルのパスとユーザIDを置き換えて実行します。相対パスは現在の作業ディレクトリを基準にします。

```bash
node backend/scripts/create-v1-token.js \
  --env-file '<バックエンド用.env.stagingのパス>' \
  --user-id '650000000000000000000001'
```

本番用は`--env-file`を本番のバックエンド環境ファイルへ変更します。指定ファイルの`JWT_DEV_SECRET`だけを使用し、シェルの環境変数や別の環境ファイルで補いません。

成功時は終了コード0で、トークンだけを標準出力へ表示します。ファイルには自動保存しません。トークンはパスワードと同様に管理し、ソースコード、共有文書、ログへ転記しないでください。使用方法と接続確認は[v1 API利用ガイド](v1.md#3-投稿前に接続を確認する)を参照してください。

このツールはDBへ接続せず、ユーザの登録や権限変更を行いません。発行に成功しても、対象ユーザの状態やルームへのアクセス権によってAPIが拒否される場合があります。

## 有効期限と利用停止

トークンは無期限です。ユーザID、`developer`ロール、発行日時を含め、HS256で署名します。有効期限の項目は付けません。

- トークン単位の失効機能はありません。再発行しても以前のトークンは無効になりません。
- 通常画面のログアウトやパスワード変更では失効しません。
- ユーザのロール変更・論理削除によりAPI利用を停止できます。元の状態に戻すと以前のトークンも再び使用できます。
- `JWT_DEV_SECRET`を変更してバックエンドへ反映すると、以前の秘密値で発行した全トークンが使用できなくなります。

環境を分離する場合は、ステージングと本番で異なる`JWT_DEV_SECRET`を使用してください。ファイル名だけではトークンを分離できません。

## 失敗した場合

失敗時は終了コード1で、標準エラーに理由を表示します。トークンは出力しません。引数は`--help`で確認できます。

- `INVALID_ARGUMENTS` / `INVALID_USER_ID`: 必須引数とユーザIDの形式を確認します。
- `ENV_FILE_UNREADABLE`: ファイルのパスと読取権限を確認します。
- `ENV_VALUE_REQUIRED`: 指定ファイルの`JWT_DEV_SECRET`が空でないことを確認します。
