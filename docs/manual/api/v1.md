# v1 API利用ガイド

外部システムやプログラムから、指定したルームへ投稿・返信・メディア添付を行うための手順です。HTTPリクエストを送信できるクライアントまたはプログラムを使用します。

このガイドでは代表的な利用手順を説明します。全APIの入力条件・応答・制約は[v1 API仕様](../../spec/backend/api/v1.md)を参照してください。管理者によるトークン発行は[発行手順](v1-token.md)で説明します。

## 1. 利用前の準備

認証用のトークンは、管理者に発行を依頼してください。通常の画面ログイン用トークンではなく、v1 API専用のトークンが必要です。

利用開始前に、次の情報を準備・確認します。

| 必要な情報 | 確認すること |
| --- | --- |
| API接続先 | 利用する環境のベースURL |
| 認証トークン | 利用するアカウント用に管理者が発行したv1トークン |
| フロアID・ルームID | 投稿先のタイムラインURLから確認する`floor_id`・`room_id`。名称ではなくIDを使用する |
| 利用権限 | アカウントが有効で、現在のロールが「開発者（developer）」であり、対象ルームへ入室できること |
| 動作確認先 | 試し投稿してよいルームと、Web画面での確認方法 |

メンバー限定ルームでは、必要なフロアメンバー・ルームメンバーの設定も管理者に確認してください。キックされているアカウントや、削除済みのフロア・ルームは利用できません。

トークンはパスワードと同様に扱い、ソースコード、共有文書、ログ、URLへ記載しないでください。公開されるブラウザ用コードへ埋め込まず、使用するクライアントの非公開の認証設定などで管理します。外部接続にはHTTPSを使用してください。

### フロアID・ルームIDの確認

投稿先のタイムラインを開き、ブラウザのアドレスバーでIDを確認します。

```text
/floor/フロアID/room/ルームID
```

`/floor/`直後が`floor_id`、`/room/`直後が`room_id`です。URLが分からない場合は管理者へ確認してください。

## 2. リクエストの送り方

### 接続先と例の読み替え

利用する環境のベースURLに、本書の`/api/v1/...`を続けて送信します。例えばベースURLが`https://app.example.com`の場合、投稿作成の送信先は`https://app.example.com/api/v1/post/create`です。`/api/v1`を二重に付けないでください。

URLは説明用の例です。試し投稿の前に、接続先の環境と投稿先のルームを確認します。

以下のIDは説明用の例です。フロアID・ルームIDはタイムラインのURLで確認した値に、投稿IDはAPI応答の値に置き換えてください。

| 本書の例 | 置き換える値 |
| --- | --- |
| `650000000000000000000001` | 投稿先のフロアID |
| `650000000000000000000002` | 投稿先のルームID |
| `650000000000000000000003` | 操作対象の投稿ID。投稿成功時の応答などから取得する |

IDは24桁の16進文字列です。以下のJSON例にある`<...>`は説明用の置き換え箇所であり、実際に返却された値などを使用します。

### 認証と本文

すべてのv1リクエストに、次のヘッダーを付けます。`Bearer`とトークンの間には半角スペースが必要です。

```http
Authorization: Bearer <管理者から発行されたv1トークン>
Accept: application/json
```

本文をJSONで送信する場合は、次も設定します。

```http
Content-Type: application/json
```

ファイルアップロードは`multipart/form-data`を使用します。クライアントのフォーム送信機能で、文字列項目とファイル項目を設定してください。`Content-Type`の境界文字列（boundary）はクライアントに生成させます。

試し投稿でもデータが保存され、設定によって通知・翻訳・AI解析が実行されます。投稿先と公開範囲を確認し、公開してよい内容だけを送信してください。

## 3. 投稿前に接続を確認する

認証ヘッダーを付け、次のURLへ`GET`を送信します。本文は不要です。

```text
/api/v1/timeline/floor/650000000000000000000001/room/650000000000000000000002
```

HTTP `200`と投稿のJSON配列が返れば、指定ルームの一覧を取得できています。投稿がなければ`[]`です。取得できるのは指定ルームの新しい投稿から最大10件です。全投稿やフロア全体の一覧を取得するAPIはありません。

失敗した場合は投稿へ進まず、[エラーへの対処](#9-エラーへの対処)を確認してください。フロアIDとルームIDは、実際に親子関係にある組み合わせを指定します。

## 4. 文字だけの投稿を作成する

1. メソッドを`POST`、URLを`/api/v1/post/create`にします。
2. 認証ヘッダーとJSON用の`Content-Type`を設定します。
3. 次の本文を、実際のフロアID・ルームIDに置き換えて送信します。

```json
{
  "floor_id": "650000000000000000000001",
  "room_id": "650000000000000000000002",
  "content": "外部システムからの投稿です。"
}
```

成功するとHTTP `200`と、作成した投稿のJSONオブジェクトが返ります。次は応答の一部だけを抜き出した例です。

```json
{
  "_id": "650000000000000000000003",
  "content": "外部システムからの投稿です。",
  "lang": "ja"
}
```

返却された`_id`を投稿IDとして保存します。返信・更新・削除では、この値を`post_id`に指定します。成功応答は`result`や`data`で包まれていません。

- 本文`content`は必須の文字列で、最大400文字です。メディアだけの投稿でも`content: ""`を指定します。
- 本文の言語は日本語（`ja`）として扱われます。`lang`や`target_langs`を指定しても、クライアント側で言語設定を変更することはできません。
- 投稿の表示はWeb画面、または前節のルーム内一覧で確認します。翻訳やAI解析の結果は、投稿成功時点では未反映の場合があります。
- タイムアウトや`500`の場合は、直ちに同じ投稿を再送しないでください。[結果が分からない場合の扱い](#8-投稿できなかったときの未添付ファイル破棄)を確認します。

## 5. 画像・動画・音声を添付する

先にファイルをアップロードし、返されたファイル名を投稿に指定します。アップロードが成功しただけでは、タイムラインに投稿は作成されません。

アップロードと投稿は、同じ利用者・同じルームで行ってください。手元のファイル名や別の投稿に付いたファイル名を、アップロード結果の代わりに指定しないでください。

### 5.1 画像をアップロードする

次のURLへ`POST`を送信します。URLのクエリパラメータ（`?`以降）とフォーム本文の両方に、対応するIDを指定します。

```text
/api/v1/upload/image?room_id=650000000000000000000002&floor_id=650000000000000000000001
```

認証ヘッダーを付け、`multipart/form-data`の項目を次のように設定します。

| 項目名 | 種類 | 指定する内容 |
| --- | --- | --- |
| `floor_id` | 文字列 | URLのクエリと同じフロアID |
| `room_id` | 文字列 | URLのクエリと同じルームID |
| `image_file` | ファイル | 投稿するPNGまたはJPEG画像（3MB以下） |

フォームの文字列項目は、この2つのIDだけにします。代替テキストや投稿本文は、次の投稿リクエストで指定してください。

成功するとHTTP `200`と、次の構造のJSONオブジェクトが返ります。

```json
{
  "image_name": "<サーバが返した画像ファイル名>",
  "image_thumbnail_name": "<サーバが返したサムネイル名>"
}
```

この2つの値を組で保存してください。サーバが生成した名前を変更せず、次の投稿に使用します。

### 5.2 アップロードした画像を付けて投稿する

`POST /api/v1/post/create`へ、認証ヘッダーと次のJSON本文を送信します。

```json
{
  "floor_id": "650000000000000000000001",
  "room_id": "650000000000000000000002",
  "content": "現場の画像です。",
  "image_name": "<アップロード応答のimage_name>",
  "image_thumbnail_name": "<アップロード応答のimage_thumbnail_name>",
  "image_caption": "入口付近の様子"
}
```

`image_caption`は任意の画像代替テキストで、最大200文字です。HTTP `200`と投稿JSONを確認し、投稿IDを保存します。以後、この投稿に添付したファイルを未添付として破棄しないでください。

### 5.3 動画・音声を付ける場合

画像と同じく、認証ヘッダー、URLのクエリのID、フォーム本文のIDを付けてアップロードします。ファイル項目と、投稿JSONへ渡す項目だけが異なります。

| 種別 | アップロード先（POST） | フォームのファイル項目 | 投稿へ渡すアップロード応答の項目 |
| --- | --- | --- | --- |
| 動画 | `/api/v1/upload/video` | `video_file`（必須、150MB以下）、`video_subtitle_file`（字幕を付ける場合、2MB以下） | `video_name`、`video_thumbnail_name`。字幕付きの場合は`video_subtitle_name`も指定 |
| 音声 | `/api/v1/upload/audio` | `audio_file`（必須、6MB以下） | `audio_name` |

例えば動画のURLは`/api/v1/upload/video?room_id=650000000000000000000002&floor_id=650000000000000000000001`です。ファイルの許可形式は[ファイルアップロードAPI仕様](../../spec/backend/api/upload.md)を確認してください。

- 動画字幕を投稿へ付ける場合は、アップロード応答の`video_subtitle_name`と、利用者側で保持した元の字幕ファイル名を`video_subtitle_originalname`として、両方指定します。元のファイル名は最大100文字です。
- 音声には任意で`audio_title`と`audio_description`を、それぞれ最大200文字で付けられます。
- 1つの投稿・返信・付加情報に付けられるメディアは、画像・動画・音声のいずれか1種類です。動画・音声の投稿に、画像用の`image_name`や`image_caption`を残さないでください。
- v1にはメディア取得用APIはありません。メディアの表示は、対象ルームへアクセスできるWeb画面で確認します。

## 6. タグ・返信・付加情報を付ける

### ルームタグ

`POST /api/v1/roomtag`へ認証ヘッダーと次のJSON本文を送り、利用できるルームタグを取得します。

```json
{
  "floor_id": "650000000000000000000001",
  "room_id": "650000000000000000000002"
}
```

HTTP `200`でタグの配列が返ります。使用するタグの`_id`を選び、投稿または返信のJSONに`"room_tags": ["<取得したタグの_id>"]`を追加してください。他のルームのタグは指定できません。

### 返信

`POST /api/v1/reply/create`へ認証ヘッダーと次のJSON本文を送信します。`post_id`は、返信先の投稿IDに置き換えます。

```json
{
  "room_id": "650000000000000000000002",
  "post_id": "650000000000000000000003",
  "content": "内容を確認しました。"
}
```

返信にも前節のメディア項目を付けられます。成功時は返信単体ではなく、返信を含む親投稿全体のJSONが返ります。応答の最上位`_id`は投稿IDであり、返信IDではありません。v1からの返信では、`notify_all`を指定しても全員通知の指定は有効になりません。

### 付加情報

投稿に付ける場合は`POST /api/v1/post/supplement/create`を使用し、`room_id`、`post_id`、`content`を指定します。返信に付ける場合は`POST /api/v1/reply/supplement/create`を使用し、さらに`reply_id`が必要です。

返信・付加情報の更新や削除に使うIDは、親投稿の応答内から、対象データの`_id`を取得します。

| 操作対象 | 親投稿JSON内の取得元 | リクエストの項目名 |
| --- | --- | --- |
| 返信 | `replies`配列内の対象返信の`_id` | `reply_id` |
| 投稿の付加情報 | `supplementaries`配列内の対象データの`_id` | `supplement_id` |
| 返信の付加情報 | 対象返信の`supplementaries`配列内の対象データの`_id` | `supplement_id` |

必要な親IDの組み合わせや入力条件は[v1 API仕様](../../spec/backend/api/v1.md#投稿返信付加情報の作成更新削除)を参照してください。

## 7. 投稿を更新・削除する

作成者本人、または対象フロアのフロアメンバーである開発者アカウントが操作できます。ルームメンバーであることだけでは、他者の投稿を更新・削除できません。

本文を更新する場合は、`POST /api/v1/post/update`へ認証ヘッダーと次のJSON本文を送ります。

```json
{
  "room_id": "650000000000000000000002",
  "post_id": "650000000000000000000003",
  "content": "内容を更新しました。"
}
```

更新でも`content`は必須です。メディア項目を省略すると、既存の添付を維持します。画像を外す場合は`image_name: null`を追加します。動画・音声はそれぞれ`video_name: null`、`audio_name: null`です。

メディアの種類を変更する場合は、旧メディアの本体名を`null`にし、新しくアップロードしたメディアの項目を同じリクエストに指定します。旧種類の代替テキストなどを残さないでください。詳細は[メディア項目の仕様](../../spec/backend/api/v1.md#メディア項目)を参照してください。

投稿を削除する場合は、対象のルームと投稿を確認したうえで、`POST /api/v1/post/delete`へ認証ヘッダーと次のJSON本文を送ります。HTTPメソッドは`DELETE`ではなく`POST`です。

```json
{
  "room_id": "650000000000000000000002",
  "post_id": "650000000000000000000003"
}
```

成功時はHTTP `200`です。削除や添付の差し替えでは、不要となったメディアファイルも削除される場合があります。後から元に戻せることを前提に操作しないでください。

## 8. 投稿できなかったときの未添付ファイル破棄

アップロード後、入力不正などで投稿が保存されていないと確認でき、投稿を取りやめる場合に使用します。対象は、その利用者がアップロードし、どの有効な投稿・返信・付加情報からも参照されていないファイルです。

`POST /api/v1/upload/discard`へ認証ヘッダーと次のJSON本文を送ります。画像の場合は本体とサムネイル、字幕付き動画の場合は動画・サムネイル・字幕の各ファイル名を指定します。

```json
{
  "floor_id": "650000000000000000000001",
  "room_id": "650000000000000000000002",
  "file_names": [
    "<アップロード応答のimage_name>",
    "<アップロード応答のimage_thumbnail_name>"
  ]
}
```

`file_names`は1〜6件です。パスやURLではなく、アップロード応答のファイル名を指定します。

HTTP `200`の応答にある`discarded_file_names`は破棄済みまたは既に実体がないファイル、`retained_file_names`は参照中のため保持されたファイルです。保持されたファイルの削除を繰り返し要求しないでください。

破棄後に投稿し直す場合は、再度アップロードして新しいファイル名を取得してください。破棄したファイル名は再利用できません。

### タイムアウト・通信断・500で結果が分からない場合

- エラーや応答がないことだけでは、投稿が保存されていないと断定できません。重複投稿を防ぐため、作成リクエストを自動再送しないでください。
- まずWeb画面などで対象ルームの投稿状況を確認します。v1の一覧は最新10件だけなので、一覧にないことだけでも未保存とは判断できません。
- 投稿の保存や添付の成否が分からない場合は、破棄APIを呼ばず、管理者に確認を依頼してください。投稿処理が継続している間に破棄を並行実行しないでください。
- アップロード自体の応答を受け取れずファイル名が分からない場合も、名前を推測せず管理者へ相談してください。未添付ファイルの定期的な自動回収はありません。

## 9. エラーへの対処

まずHTTPステータスと、JSON応答の`error.code`を確認します。エラー応答の形式は[REST API共通規約](../../spec/backend/api-conventions.md#エラー応答)を参照してください。

| 応答 | 確認・対処 |
| --- | --- |
| `400 INVALID_PARAMS` | IDの形式・親子関係、必須の`content`、タグの所属、メディアの組み合わせ、アップロード時のURLのクエリと本文のIDを確認する |
| `401 TOKEN_INVALID` | v1専用トークンとヘッダーの指定を確認する。解消しなければ管理者へ利用者の状態とトークンを確認してもらう |
| `401 TOKEN_EXPIRED` | 管理者にトークンの再発行を依頼する |
| `401 INVALID_PERMISSION` / `403 FORBIDDEN` | 開発者ロール、対象ルームへの入室権、キック状態、対象データの更新・削除権限を管理者に確認してもらう |
| `404` | URL、HTTPメソッド、対象ID、削除状態を確認する |
| `413 FILE_TOO_LARGE` | ファイルサイズを上限以下にする |
| `500 INTERNAL_SERVER_ERROR` / 応答なし | 自動再送や未添付ファイルの破棄を止め、保存状況を確認して管理者へ相談する |

URLやメソッドを誤ると、JSONではなくHTMLの`404`が返る場合もあります。JSONとして読めない応答も、成功として扱わないでください。

管理者へ問い合わせる際は、発生日時、接続環境、操作したAPI、対象ID、HTTPステータス、エラーコードを伝えます。トークン、認証ヘッダー、ファイルや投稿本文の機密情報は問い合わせ資料へ含めないでください。

トークンの漏えいが疑われる場合は利用を止め、直ちに管理者へ連絡してください。通常画面でのログアウトやパスワード変更だけでは、v1トークンは失効しません。
