# 外部連携用v1 API（`/api/v1`）

## 概要

`developer`ロール向けに、タイムライン操作とメディアのアップロードを提供します。通常APIとは別の認証を使用します。

## 共通条件

### 提供範囲

`developer`ロール向けに18エンドポイントを提供する。通常APIと共通のサービスで、ルーム認可、DB更新、通知、翻訳、AI解析、メディア処理を行う。v1固有の認証・入力・応答は本書に従う。

### 認証・ルームへのアクセス権

- `Authorization`ヘッダのトークンを`JWT_DEV_SECRET`で検証する
- 現行ミドルウェアはヘッダを空白で分割した2番目の値を使い、scheme名が`Bearer`かは確認しない
- トークンペイロードの`user_role`が厳密に`developer`であることを確認する
- トークン検証後に、対応するユーザが有効で、DB上の現在ロールも`developer`であることを確認する。後続処理ではDB由来のユーザIDとロールを使用する
- `session_version`は照合しない。パスワード変更等による通常JWTと同じ世代失効は適用されない
- 全エンドポイントで通常APIのルームアクセス規則を使用する。論理削除済みルーム／フロア、キック済みユーザ、メンバー限定ルームへ入室できないユーザは拒否する
- 作成・更新・削除では、認可済みルームから投稿、返信、付加情報の順に有効な対象を確認する。入力した親子IDの所属が一致しない場合や、いずれかが論理削除済みの場合は変更しない

更新・削除は、フロアメンバーまたは対象データの作成者本人が更新・削除できる。ルームメンバーであることだけでは、他者が作成したデータを更新・削除できない。作成操作はルームアクセス権があれば実行できる。

バックエンドはv1のレート制限を行わない。必要な制限は、対象環境のリバースプロキシで設定する。

### 共通エラー

| HTTP | エラーコード | 主な条件 |
| --- | --- | --- |
| 400 | `INVALID_PARAMS` | ID、本文、親子関係、ルーム／フロア整合性、メディア、multipart入力等が不正 |
| 401 | `TOKEN_INVALID` / `TOKEN_EXPIRED` | トークンなし、形式・署名不正、期限切れ、対応する有効なユーザなし |
| 401 | `INVALID_PERMISSION` | タイムラインの作成・更新・削除、アップロード、未添付メディア破棄でルームアクセス権または更新・削除権限がない |
| 403 | `FORBIDDEN` | トークンペイロードまたはDB上の現在ロールが`developer`ではない。ルームのタイムライン一覧と`RoomTag`一覧では、キック済みまたはメンバー限定ルームへの所属がない場合も含む |
| 404 | `NOT_FOUND` | 対象データなし、または未定義API |
| 413 | `FILE_TOO_LARGE` | アップロードのファイルサイズが上限超過 |
| 500 | `INTERNAL_SERVER_ERROR` | DB、変換、外部処理、ファイル操作等の予期しない失敗 |

共通エラーJSONは[REST API共通規約](../api-conventions.md)を参照する。対象の種類によって、存在しない対象や論理削除済み対象が`400 INVALID_PARAMS`になる場合がある。

### 投稿・返信入力の共通契約

#### 基本項目

| 項目 | 契約 |
| --- | --- |
| `floor_id`、`room_id`、`post_id`、`reply_id`、`supplement_id` | 必須と記載した箇所では24桁16進数のMongoDB ObjectId文字列が必要 |
| `content` | 作成・更新で必須の文字列。`null`不可、最大400文字 |
| `lang` | クライアント指定を使用せず、`ja`を設定 |
| `target_langs` | クライアント指定を使用しない。フロア設定と現在そのルームへSocket接続中の言語からサーバ側で算出し、`ja`を除外 |
| `room_tags` | 投稿／返信で任意。ObjectId文字列の配列。指定時は有効かつ対象ルーム所属であることを確認 |
| `animation` | 投稿／返信で任意。`move-and-erase`または`null` |
| `notify_all` | 返信ではクライアント指定を使用せず、`false`として処理 |

- 投稿の`room_tags:null`は空配列として扱う
- 返信更新の`room_tags:null`と`animation:null`は既存値を維持する
- 更新では明示した変更可能項目だけを変更し、省略した項目は認可後に取得したDBの現在値を維持する
- 成功時はユーザ等の関連情報を展開した親投稿JSONを`200`で返す。論理削除済みの返信・付加情報と内部管理項目は応答から除く

#### メディア項目

メディア項目は、入れ子にせずリクエスト本文の直下に指定する。

| 種別 | 項目 |
| --- | --- |
| 画像 | `image_name`、`image_thumbnail_name`、`image_caption` |
| 動画 | `video_name`、`video_thumbnail_name`、`video_subtitle_originalname`、`video_subtitle_name` |
| 音声 | `audio_name`、`audio_title`、`audio_description` |

- `image_caption`、`audio_title`、`audio_description`は文字列または`null`で、最大200文字である
- `video_subtitle_originalname`は文字列または`null`で、最大100文字である
- 1データが保持できるのは画像、動画、音声のいずれか1種類だけである
- 画像と動画は本体とサムネイルを組で保持する。動画字幕は作成時に`video_subtitle_originalname`と`video_subtitle_name`を組で指定する。更新時は省略項目を維持した最終状態で両方を設定するか、両方を未設定にする必要があり、字幕の追加または字幕だけの解除では両項目を指定する。字幕だけ、captionだけ、titleだけ等を作成時に指定できない
- 作成・更新で新しいファイル名を指定した場合、保存先の実体、許可拡張子、発行ユーザ、対象フロア／ルーム、他の有効データからの参照を共通サービスで確認する
- 更新では明示したメディア項目だけを変更する。対象メディアの本体ファイル名へ`null`を明示した場合だけ、その種類の全項目を`null`にして解除する。空文字は`null`として扱う
- 種類を変更する場合は、旧メディアの本体ファイル名を`null`にし、新しい種類のメディア項目を同じリクエストで指定する。旧メディア種別を省略したまま別の種類を追加すると、最終状態が複数種類になるため拒否する
- 置換・削除対象のファイルは、物理削除の直前にも同じルーム内の参照を確認する。参照中または確認失敗時は保持する

## API

### タイムライン・ルームタグ一覧

#### `GET /api/v1/timeline/floor/:floor_id/room/:room_id`

- 指定ルームの有効な投稿を作成日時降順で最大10件返す
- パスの`floor_id`と`room_id`を基準にする。GETリクエスト本文の同名項目は任意の互換入力として受け付け、指定時はパスと一致する必要がある
- ルームが指定フロアに所属することを確認し、通常APIと同じ関連情報を展開した投稿を配列で返す

#### `POST /api/v1/roomtag`

- ボディ `floor_id`、`room_id`を受け取り、指定ルームの有効な`RoomTag`を返す
- `floor_id`は互換入力として形式を確認する。実際のフロアはルームから導出する
- 応答は`order`昇順、同順位では`created_at`降順の配列である

### 投稿・返信・付加情報の作成・更新・削除

| メソッド・パス | 必須ID | 処理とSocket イベント |
| --- | --- | --- |
| `POST /api/v1/post/create` | `floor_id`, `room_id` | 投稿作成、`POST_CREATE` |
| `POST /api/v1/post/update` | `room_id`, `post_id` | 投稿更新、`POST_UPDATE` |
| `POST /api/v1/post/delete` | `room_id`, `post_id` | 投稿論理削除、`POST_DELETE` |
| `POST /api/v1/post/supplement/create` | `room_id`, `post_id` | 投稿付加情報作成、`SUPPLEMENT_CREATE` |
| `POST /api/v1/post/supplement/update` | `room_id`, `post_id`, `supplement_id` | 投稿付加情報更新、`SUPPLEMENT_UPDATE` |
| `POST /api/v1/post/supplement/delete` | `room_id`, `post_id`, `supplement_id` | 投稿付加情報論理削除、`SUPPLEMENT_DELETE` |
| `POST /api/v1/reply/create` | `room_id`, `post_id` | 返信作成、`REPLY_CREATE` |
| `POST /api/v1/reply/update` | `room_id`, `post_id`, `reply_id` | 返信更新、`REPLY_UPDATE` |
| `POST /api/v1/reply/delete` | `room_id`, `post_id`, `reply_id` | 返信論理削除、`REPLY_DELETE` |
| `POST /api/v1/reply/supplement/create` | `room_id`, `post_id`, `reply_id` | 返信付加情報作成、`REPLY_SUPPLEMENT_CREATE` |
| `POST /api/v1/reply/supplement/update` | `room_id`, `post_id`, `reply_id`, `supplement_id` | 返信付加情報更新、`REPLY_SUPPLEMENT_UPDATE` |
| `POST /api/v1/reply/supplement/delete` | `room_id`, `post_id`, `reply_id`, `supplement_id` | 返信付加情報論理削除、`REPLY_SUPPLEMENT_DELETE` |

作成・更新では上表のIDに加えて`content`が必須であり、対象種別に応じて`RoomTag`、animation、メディア項目を指定できる。削除ではIDだけを指定する。

共通サービスを共有するため、スパムワードの置換、Socket通知、対象者への通知、Google Translate、設定駆動AI解析も通常のタイムラインAPIと同じ条件で処理する。更新では、Google Translateが有効で本文または原文言語（`lang`）が変わった場合だけ、既存の翻訳を空配列へ戻して再翻訳を試行する。Google Translateが無効な場合は保存済みの翻訳を保持する。各外部機能は対応する機能フラグと設定が有効な場合だけ実行する。

### アップロード

形式検証、変換、同時添付、未添付ファイルの扱いは[ファイルアップロードAPI](upload.md)に従う。

3つのファイルアップロード APIは、ファイルを受信する前に`developer` ユーザとルームアクセス権を確認する。

#### 共通入力

- 形式: `multipart/form-data`
- クエリ `room_id`: 必須。認可対象ルーム
- クエリ `floor_id`: 任意。指定時はルームから導出したフロアと一致すること
- ボディ `floor_id`、`room_id`: 必須。認可済みのフロア／ルームとObjectIdとして一致すること
- 保存先: `MEDIA_PATH/<floor_id>/<room_id>/`
- ファイル名: 元のファイル名を使用せず、サーバ側で衝突耐性のある名前を生成する
- ボディとクエリのID表現は、認可済みDBオブジェクトから得た小文字の正規形へ統一してから保存する

#### `POST /api/v1/upload/image`

- ファイル項目: `image_file`、必須
- 上限: 3 MB
- 申告MIME: PNG／JPEG
- PNG／JPEGの署名、デコード結果、画素数を確認し、メタデータを引き継がず同形式へ再エンコードする
- 応答: `image_name`、`image_thumbnail_name`

#### `POST /api/v1/upload/video`

- ファイル項目: `video_file`、必須
- ファイル項目: `video_subtitle_file`、任意
- 上限: 動画150 MB、字幕2 MB
- 動画のMIMEと拡張子、字幕のMIMEと拡張子を確認する
- 約1秒地点から長辺720px以内のPNGサムネイルを生成する
- 応答: `video_name`、`video_thumbnail_name`、`video_subtitle_name`

#### `POST /api/v1/upload/audio`

- ファイル項目: `audio_file`、必須
- 上限: 6 MB
- 許可MIMEを確認する
- 保存名の拡張子が`.mp3`以外の場合はMP3へ変換し、原本の削除を試みる
- 応答: `audio_name`

ファイルアップロード全体の詳細は[ファイルアップロードAPI](upload.md)を参照する。

### `POST /api/v1/upload/discard`

投稿処理が失敗し、アップロード済みファイルがどのデータからも参照されていないことが確定した場合に使用する。

- 形式: `application/json`
- ボディ `floor_id`、`room_id`: 必須のMongoDB ObjectId文字列
- ボディ `file_names`: 1～6件の文字列配列。重複は1件として処理する
- 現在のルームアクセス権を確認する
- JWT ユーザ自身のIDを含むサーバ生成形式のファイル名だけを受け付ける
- 全ファイル名とDB参照状態を確認してから削除を開始する
- 有効なデータから参照中のファイルは保持し、`retained_file_names`へ入れる
- 未参照または実体が既にないファイルは処理済みとして`discarded_file_names`へ入れる
- 保存先外を示す名前、他ユーザが発行した形式の名前、確認不能な入力は拒否する

v1にはメディア取得エンドポイントやメディアアクセスCookieの発行機能はない。v1 クライアントは投稿と失敗時破棄だけを行い、メディア表示は通常のWeb クライアントが既存の認可付き`/media`経路で行う。
