# 更新のお知らせ・ルームの絵文字

既存の返信表示を保ち、代替テキスト・付加情報・リアクションの更新を任意で知らせる。投稿欄と共同編集の仕様と組み合わせて使う。

## 既存との違い

| 項目 | 今回の差分 |
|---|---|
| 返信 | 並び順と接続線を変更しない。新しい返信が上、最上位の親投稿を再表示。 |
| 代替テキスト | 説明の枠内にも従来のリアクションアイコン。元投稿のリアクションと別に保存・集計。 |
| 付加情報 | 従来の位置を保つ。本文の共同編集はルーム設定で許可。共通の「付加情報」見出しは置かず、各情報のタイトルを表示。 |
| 更新のお知らせ | タイムライン設定に、このルーム・自分の閲覧用オプションを追加。初期状態はオフ。 |
| 絵文字候補 | 既存のフロア／ルーム単語管理で、絵文字グループを指定。投稿・返信本文への挿入とリアクションに同じ候補を使う。 |

## 更新通知

- `roomUpdatePreferences[roomId]` を既存のブラウザ保存に含める。共有設定・プッシュ通知ではない。
- `enabled` は false、`scope` は related（自分が投稿・返信・反応したもの）、代替テキストと付加情報は true、リアクションは false が既定。all は現在の表示条件に合うもの。
- 読込済み投稿とsocketで受信した更新を比較し、同じ最上位親への更新を1件にまとめる。投稿の時刻や並び順を書き換えない。
- 最初は「新しい更新があります」。利用者が「表示」を押すと更新カードを出す。「対象を見る」で対象の説明／付加情報へスクロールし、キーボードフォーカスも移す。
- 非表示のAI付加情報、表示しない代替テキスト、絞り込み対象外の投稿は通知に出さない。自分自身のリアクション追加も除く。返信の従来通知は継続。
- オフでは従来のリアクション通知を維持。新機能でリアクション通知を有効にした場合のみ、旧通知との重複を抑止する。
- メモリ上に最大100対象を保持。通知本文はブラウザ永続保存しない。閲覧中に受信し、既に読み込んだ投稿のみが対象。閉じていた間／未読込投稿の更新履歴、複数端末同期は対象外。
- 更新通知は復元履歴ではない。共同編集の履歴復元・フロア編集者権限は別途検討。

## 絵文字とリアクション

- Floor/RoomQuickTextGroup に `is_emoji`、各Itemに `emoji` を任意追加。既存項目はそのまま通常の単語。
- 管理者がグループ編集の「絵文字として使うグループ」を選択し、候補に絵文字と名称を登録する。通常の単語候補と絵文字候補は投稿欄で重複表示しない。
- 設定したグループがないルームでは従来5候補を維持。設定グループがあり候補0件なら空の候補となる。
- フロア設定は新規ルーム作成時に複製する。その後は各ルームで独立して管理し、既存ルームに一括変更しない。閲覧中の別端末には再読込／ルーム再入室で反映。
- ルーム候補のリアクション識別子は `room:<itemId>`。候補が削除されても過去の反応は保存時の絵文字／名称で表示できる。候補が現存する間は現在の候補表示を優先する。本人が付けた反応は候補削除後も取り消せる。
- 代替テキストへの反応は `alternative_reactions` と `media_kind` で画像・動画・音を区別する。投稿、返信、投稿の付加情報、返信の付加情報の各対象を扱う。
- 既存のリアクションは旧APIを保ち、カスタム絵文字・説明への反応だけ共通のresource APIを追加。本人または既存管理者の削除権限、公開／限定ルームの権限を確認する。ゲストのIDを認証トークンから取る。
- ゲストの認証更新後の再送は更新済みトークンを使用する。[APIクライアント](api.md#apiクライアント)を参照。
- 絵文字のみを許可するゲスト投稿も、同じルーム候補を検証に使う。一般テキストを許す変更ではない。
- 操作には対象名、絵文字の名称、`aria-pressed`、チェック状態、フォーカス表示を付ける。VoiceOverの実発話は今回未確認。

## リアクションの操作

- 代替テキストも他の付加情報と同じく、反応数の下にリアクション→編集の順で横並びにする。操作アイコンは32px、余白も揃える。配置のみ変更し、各操作の権限とコールバックは維持する。
- 代替テキストも既存の `add_reaction` アイコンを使う。対象はツールチップと読み上げ名「代替テキストへのリアクション」で示す。
- 候補は既存どおりアイコンの上側へ横並びで開く。本文を押し下げない。
- 既存方式に揃え、開くと最初の候補へフォーカスし、閉じる／Escape／外側クリックでアイコンへ戻す。同じアイコンでも開閉できる。
- 開閉・横並び表示の変更は、保存・取消APIや返信の順序から独立している。

## 候補が多い場合の横スクロール

- リアクション候補は一列を保ち、収まらない分だけ横スクロールする。タッチの横スワイプ・トラックパッド・Tabで末尾まで移動できる。
- 候補枠の固定320px上限を外し、画面とカラムの利用可能幅（40pxの余裕を除く）まで広げる。候補が少ない場合は内容の幅だけ使う。`fitPickerToViewport` は表示時・ウィンドウ変更・親要素の幅変更時に幅と横位置を補正し、連続した計算は最後のものだけ反映する。
- 候補が隠れている側に左右矢印を表示し、押すと表示幅の約75%進む。端ではその側の矢印を幅ごと取り除き、空白を残さず、候補が全部収まる場合は両方とも表示しない。日英の読み上げ名を付け、フォーカス中の矢印が消える場合は端の候補へ移す。`updateScrollState`で現在位置を反映し、`scrollChoices`で移動する。
- 閉じるボタンをスクロール領域から分離し、候補と一緒に流れないようにする。Tab循環・Escape・外側クリック・対象名・選択状態は維持する。
- 投稿欄の絵文字は従来の折り返し表示を維持。この変更は共通ReactionPickerのみ。

## 文字サイズと見出し

- 代替テキストの見出し・本文は親の文字サイズを継承する。標準表示では投稿本文と同じ14pxで、利用者の文字サイズ設定も引き継ぐ。
- 投稿・返信の共通見出し「付加情報」と、その線・余白を除く。各付加情報のタイトル・作成者は維持する。

## 列幅の変更への追従

`observePickerContainers` が親要素の幅を ResizeObserver で監視し、PCの列境界を動かしても開いた候補の幅・横位置・スクロール矢印を再計算する。高さだけの変化は再計算せず、閉じた際に監視を解除する。
