# タグの引き継ぎ仕様

## 概要

投稿・返信ダイアログを開いたときの初期選択タグと、「元投稿」「前回投稿」「クリア」による選択変更、絞り込みタイムラインからの自動付与、保存後の履歴更新を定義する。

### 適用範囲

- ログインユーザとゲストによる投稿作成
- ログインユーザによる投稿編集
- ログインユーザとゲストによる返信作成
- ログインユーザによる返信編集
- 通常投稿と「流す」投稿
- デスクトップのカラム操作とモバイルの現在タブ操作

「ゲストはリアクションのみ」が有効なルームをゲストで利用する場合は投稿・返信ダイアログのタグ入力欄自体を表示しないため、本仕様の選択操作は適用しない。

## 動作・適用条件

### 用語と状態

| 用語 | 保存先／算出元 | 用途 |
| --- | --- | --- |
| 自分の直前投稿のタグ | 読み込み済みの`timeline.filters[].posts`から都度算出 | 新規投稿の初期選択と「前回投稿」 |
| 持ち越しタグ | `store.tag.list` | 投稿編集・返信の「前回投稿」 |
| 絞り込みタグ | 投稿ボタンから渡す`presetTagIds` | 「表示する」絞り込みから開く新規投稿の初期選択 |
| 元投稿タグ | 返信元投稿の`room_tags` | 返信の「元投稿」 |
| 選択タグ | 各ダイアログ内の`roomTags` | 保存要求へ送る現在のタグID配列 |

自分の直前投稿のタグと持ち越しタグは別の状態である。新規投稿の初期選択には持ち越しタグをフォールバックとして使用しない。

### 投稿のタグ選択

#### 新規投稿の初期選択

連続投稿中は直前の保存応答の確定タグ（空配列を含む）と選択元を最優先する。新しく開始する場合、列の `postTagMode=empty` は未選択、`auto`（旧保存値を含む既定値）は次の優先順位とする。

| 優先順位 | 条件 | 初期選択 |
| --- | --- | --- |
| 1 | `presetTagIds`が1件以上 | 絞り込みタグ |
| 2 | 絞り込みタグなし、かつ読み込み済みデータに自分の投稿あり | 自分の直前投稿のタグ |
| 3 | 上記以外 | 未選択 |

- 最新投稿を探索するための追加APIは呼び出さない。
- 通常投稿と「流す」投稿で同じ優先順位を使用する。

#### 自分の直前投稿の探索

- 同一ルームで読み込み済みの`timeline.filters[].posts`を全カラム横断で探索する。現在選択中のカラムだけには限定しない。
- `created_at`を日時として解釈し、最も新しい自分の投稿を採用する。日時がない、または解釈できないデータは時刻`0`として扱う。同時刻の場合は先に探索した投稿を維持する。
- 通常投稿と「流す」投稿を対象とする。
- `origin_id`を持つ返信と、返信通知・リアクション通知カードを対象外とする。
- 同じ投稿が複数カラムに存在する場合は投稿ID単位で重複を除外する。
- ログインユーザは投稿の`user`、ゲストは`guest_id`を現在の利用者と照合する。
- `TAG_UPDATE`などで表示中データが更新されていれば、更新後の`room_tags`を参照する。

#### 絞り込みタグの抽出

- 「表示する」絞り込みで`displayOrder`に含まれるタグIDを抽出する。フォームへ適用するときに削除済みタグと重複を除外する。
- 「表示しない」絞り込み（`filterMode: exclude`）では自動付与しない。
- 特殊条件の`notags`、`animation`、`fav`はタグIDとして扱わない。
- デスクトップのカラム投稿ボタンとモバイルの現在タブ投稿ボタンは同じ抽出処理を使用する。
- 通常投稿ボタンと「流す」投稿ボタンのどちらにも同じ絞り込みタグを渡す。
- キーボードショートカット（`n`／`m`）は現在のフィルタから`presetTagIds`を渡さない。この経路では自分の直前投稿のタグ、または未選択から開始する。

#### 「前回投稿」

- 新規投稿では、自分の直前投稿のタグで選択状態を置き換える。
- 自分の直前投稿のタグがない場合は無効にする。
- 絞り込みタグを初期選択していても、押下後は自分の直前投稿のタグへ置き換える。

#### 連続投稿

- 成功応答の投稿IDと `room_tags` を確認してから次のフォームを開く。送信した本人の最終タグ（空配列も含む）と選択元を引き継ぐ。タイムラインの反映を待って再探索しない。
- 不完全な成功応答・通信失敗では下書きを保ち、自動再送や次フォームへの遷移をしない。
- キャンセル・通常終了・ルーム移動・再読み込みで区間を終える。投稿確認パネルの開閉では区間を終えない。

#### 投稿・返信に共通する選択元表示

- 「クリア・このタブ・元投稿・前回投稿・貼り付け」は1段配置。狭い幅や拡大文字ではボタン列だけを横スクロールする。
- 初期値の実際の出所を1つだけ青背景・内枠・選択元テキストと `aria-pressed` で示す。未選択ならクリア、列由来ならこのタブ、以前の自分の投稿なら前回投稿。
- 個別チェック変更で全強調と選択元テキストを消す。空集合へ手動変更してもクリアを推定選択しない。手動選択という状態名は表示しない。
- 「このタブ」は投稿開始元のタグを置換適用する。除外条件でも明示操作なら指定タグを使うが、従来の自動選択では除外条件のタグを使わない。全体条件やキーワードからタグを推測しない。タグがなければ無効。
- ショートカットは従来どおり特定の列タグを渡さないため、このタブは無効。投稿編集・返信にも同じ5ボタンを常に表示する。開いた列のタグ条件（除外条件も含む）を「このタブ」を押したときだけ適用する。通常列・タグなし条件・発生元の列が不明・投稿詳細画面では無効にする。PCでは選択中の列ではなく、操作した投稿カードの列を使う。
- 投稿編集・返信の初期選択は従来どおり維持し、列タグを自動適用しない。ダイアログを開くたびに発生元を更新し、前回の列タグを持ち越さない。
- ボタン操作は列の自動選択設定を書き換えない。アプリ内の「タグのコピー」が貼り付け元であり、OSクリップボードではない。

#### 投稿の確認

- 新規投稿成功の通知に「投稿を表示」を付ける。表示条件との不一致を確認できる場合はその旨を示す。送信成功はAI回答の完了を意味しない。
- 投稿フォームに「直前の投稿を表示」を置く。確認パネルは既存の認証付き詳細APIで取得し、通常の投稿・返信・付加情報を閲覧用に表示する。更新は再取得のみ。
- 元のタブ、スクロール、入力内容、添付、タグ、連続投稿状態を保ち、閉じると元の操作へフォーカスを戻す。送信・録音・文字起こし中は開かない。

#### 投稿編集

- 編集対象投稿の`room_tags`を初期選択し、「元投稿」を強調する。「元投稿」は編集開始前のタグに戻す。空の保存済みタグにも戻せる。
- 絞り込みタグと自分の直前投稿のタグによる新規投稿用の初期選択は適用しない。
- 「前回投稿」は自分の直前投稿ではなく`store.tag.list`を使用する。

#### 投稿保存後の持ち越しタグ

- ログインユーザの投稿作成・編集成功時に、APIレスポンスの`room_tags`で`store.tag.list`を更新する。
- ゲスト投稿作成成功時も同様に更新する。
- 投稿保存に失敗した場合は更新しない。

### 返信のタグ選択

#### 初期選択

| 操作 | 初期選択 |
| --- | --- |
| 新規返信 | 未選択 |
| 返信編集 | 編集対象返信の`room_tags` |

- 新規返信では`store.tag.list`、返信元投稿、直前の返信のタグを自動選択せず、「クリア」を強調する。
- 返信編集の初期値は返信自身の保存済みタグであり、親投稿由来と誤表示しないようボタンを強調しない。「元投稿」は従来どおり親投稿を指す。
- 返信作成・編集とも、元投稿・前回投稿・貼り付け・クリアの操作後は該当ボタンを強調し、個別のチェック変更で解除する。タグ集合が同じでも選択元を推定しない。
- 返信作成・編集の成功時は`store.tag.list`を更新しない。
- したがって、返信の保存タグは次の返信へ自動的には持ち越さない。

#### 「元投稿」と「前回投稿」

- 「元投稿」は返信元投稿の`room_tags`で選択状態を置き換える。元投稿タグがなければ無効にする。
- 「前回投稿」は`store.tag.list`で選択状態を置き換える。持ち越しタグがなければ無効にする。
- 返信の「前回投稿」は、直前の返信ではなく、最後に成功した投稿作成・投稿編集で記録されたタグを意味する。

### 共通操作

#### クリア

- 「クリア」はダイアログ内の選択タグだけを空にする。
- 自分の直前投稿のタグ、持ち越しタグ、元投稿タグ、コピー済みタグは変更しない。

#### コピー済みタグの貼り付け

- 「貼り付け」は選択タグをコピー済みタグで置き換える。
- 貼り付けだけは現在のルームタグ一覧に存在するIDへ絞り込み、重複を除外する。
- 詳細は[タグコピー貼り付け仕様](tag-copy-paste.md)を参照する。

### 持ち越しタグのライフサイクル

- `store.tag.list`はルートストアに保持し、`localStorage`の`iseeetl_store`へ保存する。
- ページを再読み込みした場合は保存状態から復元できる。
- タイムラインでルームリソースを初期化すると空にする。このため、ルームへ入り直した後は保存されていた値を持ち越し続けない。
- ログアウト時はストアと`localStorage`の両方から消去する。

### バックエンド検証との関係

- ダイアログ反映時にタグIDを現ルームの有効タグへ絞らないため、無効・別ルームのIDが保存要求に残るとバックエンド検証で失敗する場合がある
- 投稿・返信の作成・更新では、送信する全タグIDが有効で、URLのフロア／ルームに属するルームタグであることをバックエンドで検証する。
- ログインユーザ用APIとゲスト用APIのどちらにも同じ所属検証を適用する。
- 検証に失敗した場合、投稿・返信は保存しない。
