# UI規約、アクセシビリティ、i18n

## 概要

この文書では、フロントエンド全体で共有するUIスタイル、操作補助、表示言語、翻訳済みデータと静的HTMLの扱いを定義します。画面固有の表示と操作は[画面仕様](screens/README.md)、アプリ初期化は[フロントエンド概要](overview.md)、保存状態は[状態管理](state.md)を参照してください。

## 動作・適用条件

### UIライブラリとスタイルの責務

- UI部品は`src/components/ui/`の独自の`Ui*`部品と意味に合うHTML要素を基礎とし、外部UIフレームワークへ依存しない
- `main.js`はsplitpanesのCSSと`src/styles/`配下の共通スタイルを一元的に読み込む
- `ui-components.css`は、複数チャンクで使う`UiProgress`と`body`直下へ移す`UiTooltip`のスタイルを固定順で一元管理する
- `main.js`は次の共通スタイルをグローバルに読み込む
  - `override.css`: 共通のエラー色、フォーカス表示、範囲選択色
  - `common.css`: アプリ共通レイアウト、`.view`、リンク、ページャ、レスポンシブ表示
  - `dialog.css`: `UiDialog`のパネル、タイトル、本文、アクション、端末別表示
  - `field.css`: `UiField`、ブラウザ標準の入力欄、チェックボックス、不可視ラベル、`.screen-reader-only`
  - `management.css`: 管理一覧、管理ページャ、論理削除表示、管理用テーブル
- アプリ共通のレイアウトは`App.vue`、部品固有の見た目は各コンポーネントの`scoped`スタイルで定義する
- 複数機能で使うクラスは責務に対応する共通CSSへ置き、単一コンポーネントだけのクラスを共通CSSへ追加しない
- Material IconsとMaterial Symbolsのフォント読込は`frontend/index.html`で維持し、表示には`UiIcon`だけを使用する
- 管理画面の一覧状態、ブラウザ標準の検索フォーム、ページャの操作名と画面幅に応じた表示は
  [管理一覧・検索共通仕様](management-list.md)を参照する

### フォーカスと背景操作の制御

- サイト全体のアクセシビリティ適合は表明していません。利用するブラウザと支援技術での確認が必要です。

#### `UiDialog`と`overlayStack`

`UiDialog`がダイアログ単体の公開契約を、`overlayStack.js`が複数ダイアログを含む共通制御を担当します。

| `UiDialog`の指定 | 現行動作 |
| --- | --- |
| `open` | `true`の間だけ表示し、管理スタックへ登録する |
| `initial-focus` | パネル内セレクタで初期フォーカス先を指定する。無効または未指定なら最初の操作可能要素、存在しなければパネル |
| `close-on-escape` | 最前面での`Escape`による`request-close`を許可する |
| `close-on-backdrop` | 背景クリックによる`request-close`を許可する |
| `title-id`／`description-ids` | パネル内の見出しと説明を`aria-labelledby`／`aria-describedby`へ関連付ける |

- `overlayStack`は最前面ダイアログだけに`Escape`とTab循環を適用し、背面パネルへ`inert`と`aria-hidden`を設定する
- `overlayStack`は登録順にダイアログラッパー、背景、パネルのz-indexを更新し、ページ側の装飾や操作がダイアログより前へ出ないようラッパー単位で重なりの基準（スタッキングコンテキスト）を管理する
- 最初のダイアログ表示時に文書スクロールを抑止し、Vuexの`inertAppContainer`を有効にする。最後のダイアログを閉じた時だけ元の状態へ戻す
- `UiDialog`は表示直前のフォーカスを保存し、閉じた時に有効な起点へ戻す。起点へ戻せない場合は残っている最前面パネルへフォーカスする
- `UiTooltip`内の起点へダイアログ終了後のフォーカスを戻す場合は、復帰直後のツールチップ表示だけを抑止する。Tabなどの通常のキーボードフォーカスではツールチップを表示する
- `UiTooltip`は起点の下側を既定の表示位置とし、表示領域に収まらない場合は反対側へ切り替える。上側を優先する箇所は`placement="top"`を明示する
- `UiDialog`破棄時は管理スタックへの登録と`body`直下へ移したルートを解除し、管理スタックが空になった時は文書全体の`keydown` イベントリスナーを解除する
- `.mobile-item`／`.desktop-item`を持つ`UiButton`は、表示中にinline-flexを維持してアイコンと文言を中央配置する
- スマートフォン幅のダイアログのヘッダーに直接置くアイコンのみのボタンと、ヘッダー右側の操作グループ内のアイコンのみのボタンは円形とし、一般のアイコンのみのボタンの形状は変更しない
- ダイアログのフッターは操作を横並びの右寄せとし、直下の`.left` グループだけを左端へ分離する

#### 共通ダイアログの構成

- 作成・編集フォームは`BaseEditDialog`、確認操作は`ConfirmDialog`、メンバー一覧は`BaseMemberDialog`を使用する。
- タイムラインの投稿・返信・付加情報編集は、複数の確定操作を保ったまま共通の取消、進捗、端末別操作配置を提供する`TimelineEditorDialog`を使用する。
- 対象フロア、ルーム、ユーザ、設定などの識別が必要な場合は`DialogTargetContext`で対象名を見出し直後に示し、そのIDをダイアログの説明へ関連付ける。
- `BaseMemberDialog`では`context`スロットへ配置する
- PCで取消と確定を同じ操作群として扱う場合は`actionsAdjacent`を指定し、フッター右側へ取消、確定の順で隣接させる。896px以下ではこのフッターを隠し、`BaseEditDialog`は左上に取消・右上に確定、`ConfirmDialog`は取消を使う場合に左上・確定を右上へ表示する。`BaseMemberDialog`は896px以下でフッターを隠し、閉じる操作を左上へ表示する
- `BaseEditDialog`と`ConfirmDialog`は送信中に操作ボタン、`Escape`、背景クリックによる終了を抑止し、`aria-busy`と`UiProgress`で処理中を示す。`BaseMemberDialog`は`loadState`で読込中・一覧・0件・失敗と再試行を分け、送信中は終了を抑止して進捗を表示する。メンバー操作の呼出し側も送信中の重複実行を抑止する
- `BaseEditDialog`と`BaseMemberDialog`は送信中でなければ`Escape`と背景クリックを許可する。`ConfirmDialog`は既定では許可せず、取り消しても安全な確認だけ`closeOnEscape`と`closeOnBackdrop`を明示する
- `BaseEditDialog`と`ConfirmDialog`の初期フォーカスは`initialFocus`で指定し、`BaseMemberDialog`は見出しへ移す。指定先が無効なら`UiDialog`のフォールバックに従う。`UiDialog`は終了時に開始元へフォーカスを戻してから`closed`を通知するため、対象データの後処理や、入れ子の確認終了に続く親ダイアログの終了は`closed`後に行う
- パネル幅は`.ui-dialog`へ`--ui-dialog-width`を指定する。パネルの固定幅や表示領域余白を個別実装せず、共通の`--ui-dialog-viewport-gutter`（通常32px、896px以下16px）による最大幅・高さを維持する
- PC（897px以上）では、投稿・返信・付加情報編集、通常の作成・編集フォーム、情報・設定、メンバー一覧・招待に`ui-dialog--standard`を適用し、共通幅480pxに揃える。`BaseEditDialog`、`TimelineEditorDialog`、`BaseMemberDialog`はこの指定を共通で持つ。確認メッセージは既定幅400pxを使用する。幅の値は`tokens.css`の`--ui-dialog-width-standard`と`--ui-dialog-width-compact`で管理する。
- タグ・単語の管理一覧、AI解析設定、ヘルプ、メディア表示は、内容量に応じた既存の幅を使用する。896px以下の幅・表示領域への収まり方と、投稿編集の画面幅に合わせた表示は維持する。
- `UiDrawer`は`UiDialog`と`overlayStack`のフォーカス循環、Escape、背景クリック、スクロール抑止、開始元へのフォーカス復帰を利用し、パネルだけを画面端から表示する。アプリメニューは独自の文書イベントリスナーやフォーカス可能な要素探索を持たず、`UiDrawer`へこれらを委譲する

#### チャンク読み込み失敗時の復旧画面

`ChunkLoadRecovery.vue`は通常アプリとは別のVueインスタンスで表示されるため、`UiDialog`と`overlayStack`へ
依存せず、必要最小限の`alertdialog`制御を自己完結させる。

- 通常アプリと同じVue I18n インスタンスを使用し、見出し、理由別メッセージ、再試行を現在言語で表示する
- 表示前のフォーカスを保存し、初期フォーカスを再試行ボタンへ移す。Tab／Shift+Tabはパネル内で循環させる
- 復旧ルート以外の`body`直下要素へ`inert`と`aria-hidden`を設定し、本文のスクロールを抑止する
- コンポーネント破棄時は背景の既存属性とスクロール状態を復元し、保存した要素が有効ならフォーカスを戻す

#### `UiField`

- ラベルは`for`でブラウザ標準の操作部品へ関連付ける。既定では空欄かつ非フォーカス時に入力欄内へ表示し、フォーカス中または値がある時は入力欄の上へ移す。選択肢の案内と項目名を常に分離するフィールドは`stacked`を指定し、空欄でもラベルを上部に保つ
- `UiField`は`input`／`textarea`の`input`とブラウザ標準の `select`を含む操作部品の`change`後にラベル位置を更新し、初期値やプログラムによる値更新も再描画後に反映する。`select`の`input`では再描画せず、Vueの`change`によるモデル更新前に選択値を巻き戻さない
- 文字数表示は`counter`を指定したフィールドだけで有効にし、ブラウザ標準の操作部品の`maxlength`と現在値から更新する
- 独自の`.text-count`を表示するフィールドには、重複を避けるため`counter`を指定しない
- `UiField`で説明とエラーを`aria-describedby`へ関連付け、`aria-invalid`で入力状態を示す。未操作時には入力検証エラーを表示しない

#### アプリ共通の操作補助

- `App.vue`はメニューまたはヘルプダイアログ表示中に、背景へ`inert`と`aria-hidden`を設定する
- アプリメニューは`UiDrawer`を使用し、開いた時は先頭項目へフォーカスし、Escape、背景クリック、末尾からのTab循環、閉じた後の起点復帰を共通重ね合わせ契約で処理する。項目アイコンは`rgba(0, 0, 0, 0.54)`を使い、項目文言の黒色と区別する
- アプリメニューは通常項目とAdministrator専用項目を別の一覧に分け、専用項目を「管理者メニュー」の見出しと視覚的な境界で識別する。Administrator以外には管理者区分自体を描画しない
- 管理者メニューは、ユーザ管理、フロア管理、フロアメンバー管理、ルーム管理、ルームメンバー管理、投稿管理、スパム管理、単語管理、共通タグ管理、フロアタグ管理、ルームタグ管理、AI解析設定管理、タイムラインデータ管理の順とし、ユーザ、フロア・ルーム、投稿、タグ・AI、データ出力のまとまりを余白で区切る
- 「メニューを閉じる」は遷移一覧外のダイアログのフッターへ置き、DOM順とTab順の最後にする。項目へ重ねず、Tab／Shift+Tabはこのボタンと先頭項目の間で循環する
- Vuexの`inertAppContainer`は、`overlayStack`にダイアログがある間、アプリコンテナ全体へ`inert`を設定する
- `role="status"`／`aria-live="polite"`と`role="alert"`／`aria-live="assertive"`の不可視領域を常設し、Vuexのメッセージを通知する
- スナックバーは同じVuexメッセージ基盤を使って視覚表示を行う。通知の振り分けは[エラー処理](error-handling.md)を参照する
- 入力中、IME入力中、メニューまたは別ダイアログ表示中を除き、`?`キーでヘルプダイアログを開く。閉じた後は起点へフォーカスを戻す

### 対応言語

`LANGUAGES`を言語選択肢、言語辞書JSON、タイムラインの一時言語指定に共通利用します。

`frontend/src/i18n.js`は各言語辞書JSONを静的読込した`localeMessages`、
`createApplicationI18n(options)`、Routerの文書タイトル用に同じグローバルインスタンスを参照する
`createI18nTranslator(i18n)`を公開します。

| コード | 言語 | コード | 言語 |
| --- | --- | --- | --- |
| `ja` | 日本語 | `en` | 英語 |
| `zh` | 中国語 | `pt` | ポルトガル語 |
| `ko` | 韓国語 | `vi` | ベトナム語 |
| `fr` | フランス語 | `es` | スペイン語 |
| `sv` | スウェーデン語 | `hi` | ヒンディー語 |
| `it` | イタリア語 | `ru` | ロシア語 |
| `uk` | ウクライナ語 | `de` | ドイツ語 |
| `tr` | トルコ語 | `he` | ヘブライ語 |

- `i18n.js`は`LANGUAGES`に対応する`src/locales/{code}.json`を静的に読み込み、Vue I18nの既定言語とフォールバック言語を`ja`にする
- 言語辞書JSONが不足した場合は静的読込を解決できず、ビルドまたはモジュール読込が失敗する。該当言語だけを除外して起動継続するフォールバックはない
- `LanguageSelector`の選択肢と値は`LANGUAGES`を管理元とし、選択肢の言語名はブラウザ言語を地域コードなし・小文字へ正規化して翻訳する。未対応のブラウザ言語は英語へフォールバックし、画面の表示言語を変更しても選択肢の言語名はブラウザ言語のまま維持する
- UIで使用する翻訳キーは全言語で空でない値を持ち、文中のプレースホルダーをそろえる。成功・失敗や前・次など、操作の意味を変えない文言を使用する
- 管理画面、接続状態、復旧・エラー通知を含む固定UI文言は、現在言語のVue I18n辞書から表示する
- 件数はVue I18nの複数形選択を使い、表示する数値は`Intl.NumberFormat`で現在言語へ合わせる。`ru`と`uk`はone、few、manyの3形を選ぶ明示規則を使う
- 日付と日時は`Intl.DateTimeFormat`を使用し、現在言語とブラウザのタイムゾーンへ合わせる。
  画面がタイムゾーンを明示する場合は、そのタイムゾーンを優先する

### 初期言語の決定とHTML属性

1. `frontend/index.html`は初期値として`<html lang="ja" id="html_lang">`を出力する
2. クローラのUser-Agentに該当する場合、`App.vue`は表示言語を`ja`に固定し、Vuexの言語は変更しない
3. クローラ以外では、復元済みVuexの`user.lang`が対応言語なら、その値を表示言語にする。不正値はブラウザ言語へフォールバックして保存し直す
4. 保存済み言語がなければ、ブラウザの優先言語から地域コードを除いた値を使用する。`LANGUAGES`にない場合は`en`とし、Vuexへ保存する
5. マウント時と`$i18n.locale`変更時にHTML要素の`lang`を更新し、現在ルートの文書タイトルを再翻訳する。画面配置は言語によらずLTRを維持し、`dir`は`ltr`とする

ゲスト認証を画面マウント前に初期化する場合も同じブラウザ言語判定を使用し、初回アクセスで日本語へ固定されないようにする。

起動前の状態復元は[フロントエンド概要の起動順序](overview.md#起動順序)を参照してください。

### 言語変更と保存タイミング

#### ログインユーザ

- プロフィールダイアログで言語を選ぶと、保存前のプレビューとして`$i18n.locale`を即時変更する
- プロフィール更新APIが成功した後に、ユーザの言語をVuexへ反映し、選択値を確定する
- 確定前にプロフィールダイアログを閉じる場合は、ダイアログ表示時の言語へ戻す
- 利用者向け手順は[プロフィール](../../manual/features/profile.md)を参照する

#### ゲスト

- ゲストプロフィールで言語を選んだ時点で、`doSetLang`によりVuexと`$i18n.locale`を更新する
- ゲスト名が未設定のまま認証を初期化する場合は、解決した言語の「ゲスト」を既定名として使用する
- Vuexの保存プラグインが変更後の言語を`localStorage`へ保存するため、「保存」を押さずに閉じても言語変更は維持される
- 「保存」はゲスト名と現在の言語をゲスト状態へ反映する
- 利用者向け手順は[ゲストプロフィール](../../manual/features/guest-profile.md)を参照する

#### タイムラインの一時言語

- タイムラインの`lang={code}`クエリは、`LANGUAGES`に含まれる場合だけ表示言語を一時変更する
- 無効な値はVuexの保存済み言語へフォールバックする
- 有効な一時言語はSocket接続時の在室・翻訳対象言語と、読み上げ開始音声の言語にも使用する
- タイムライン画面を破棄すると、表示言語をVuexの保存済み言語へ戻す
- この一時変更ではVuexの保存言語を変更しない。利用者向け仕様は[タイムラインクエリパラメータ](../../manual/features/timeline-query-parameters.md)を参照する

### 翻訳済みデータの表示

UI固定文言の`$t`と、バックエンドから受け取る翻訳配列は別に扱います。翻訳配列は`translationUtil.js`で次の順に解決します。

- フロア／ルームのタイトル・説明: 原文言語が未設定、または表示言語と同じなら原文を使う。異なる場合は対象言語の翻訳を使い、なければ原文を表示する
- タグ名: 対象言語の翻訳があれば使用し、なければ元の名前を使用する
- 投稿、返信、付加情報の本文: 原文言語と対象言語が同じなら元本文、次に対象言語の翻訳、英語翻訳、元本文の順で使用する
- 翻訳が表示されていることを示す判定も、対象言語の翻訳、英語翻訳の順で行う
- 利用者が入力したタイトル、説明、本文、タグ、単語、表示名は、周囲の画面配置を変えない局所的な`dir="auto"`で混在文字列の読み順を補助する。メールアドレス、URLなどLTR固定値は必要な箇所で方向を分離する
- 単語、フロアタグ、ルームタグ、ルームの編集では保存済みの原文言語を維持する。単語の言語が未設定または非対応の場合は現在の表示言語、それも利用できなければ日本語を使用する

- タイムラインの絞り込み表示順は識別用`key`だけを保存し、特別条件の固定文言とタグ名は表示時の言語で解決する

#### 翻訳の生成と更新

翻訳の生成・再生成はGoogle Translateが有効な場合に行う。共通の単語自身は翻訳を保存しない。

| 対象 | 再生成の契機 |
| --- | --- |
| ルーム、フロアタグ、ルームタグ | 原文または原文言語の値を変更した場合 |
| フロア単語・ルーム単語 | タイトル／ラベル／`lang`を更新要求に含めた場合。同じ値でも再生成し、表示順だけの変更では再生成しない |

翻訳が無効な場合は保存済みの翻訳を保持し、単語の新規作成APIでは翻訳を空配列とする。フロアの`target_langs`変更による配下データの再翻訳は、[フロア管理の翻訳と下位データへの影響](screens/FloorManagement.md#翻訳と下位データへの影響)を参照する。

### 画面の書字方向

- 共通UIの画面配置は、ヘブライ語を含む全言語でLTRを維持する
- `he`選択時もメニュー、フォーム、ダイアログ、ページャ、タイムライン、DOM順、Tab順、方向性アイコンを反転しない
- `dir="auto"`は利用者由来の自由入力など局所的な混在文字列に限定し、共通UIの配置変更には使用しない

### 言語別の静的HTML

利用規約、プライバシーポリシー、Cookieポリシー、アクセシビリティ、お問い合わせの本文は、全16言語について
`frontend/src/content/static/{code}/`へ配置します。ヘルプ本文は外部機能の有効状態に応じた表示を行う専用画面とダイアログで
共用するため、`frontend/public/content/{code}/help.html`へ分離して配置します。

- 5文書ルートは`StaticDocumentView`を共用し、ルートメタ情報の`staticContentName`で対象本文を選択する
- Viteがビルド管理するハッシュ付きアセット URLの対応表から現在言語・現在文書だけを選び、同一オリジンで取得する。本文更新にはフロントエンドの再ビルドと配置が必要になる
- 初回取得中は`role="status"`と`aria-busy`を表示する。言語変更中は直前の本文を維持し、文書ルート変更時は新しいH1と古い本文を混在させない
- 対象言語を取得できなければ日本語を取得する。両方に失敗した場合は`role="alert"`のエラーと再試行操作を表示する
- 遅れて完了した古い言語・古い文書の応答と、画面破棄後の応答は現在の本文を上書きしない
- H1と外側の`article`はVue側が所有する。本文HTMLはH1を含めず、最初の見出しをH2とする断片とし、`article`、`main`、`script`、`style`、`iframe`も含めない
- 本文は許可タグ、許可属性、妥当な`lang`／`dir`、`http`／`https`／`mailto`／`tel`、同一オリジンのルート相対リンク、ページ内リンクだけを許可してサニタイズする
- `article`には実際に取得した本文の`lang`を付ける。言語に基づく`dir`は付けず、画面のLTR配置を継承する
- 見出し、段落、一覧、住所、リンク、表、長いURLと狭い画面の表スクロールは`static-document.css`で共通表示する
- ヘルプは専用`HelpContent`と公開HTML読込処理を使用し、機能の有効状態を示すマーカーによる項目表示を行う
- 画面固有の取得・表示仕様は[アクセシビリティ画面](screens/Accessibility.md)と[ヘルプ画面](screens/Help.md)を参照する
