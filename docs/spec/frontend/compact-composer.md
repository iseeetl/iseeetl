# 添付元とAIタグを分ける投稿欄

## 操作
PC/スマホのコメント右下に「ライブラリ・カメラ・ファイル・録音」を置く。スマホ下部は同じ処理を呼ぶ追加ショートカット。各ボタンはアイコン＋短い名称、44px以上の操作領域。下部の連続投稿/投稿は等幅で、無効状態は薄く表示する。

- ライブラリ: 保存済みの写真/動画の選択。OSのメニュー順序を固定するものではない。
- カメラ: アプリ内の撮影画面。写真/動画、前後カメラを切り替え、撮影/録画開始・停止。動画は最長30秒。写真はJPEG、動画はブラウザが対応するMP4またはWebM。スマホではブラウザの表示領域いっぱいに撮影画面を広げる（OSのカメラアプリへの切替ではない）。カメラ権限が必要で、動画ではマイク権限も必要。権限待ち15秒で案内を出し、遅れて許可された機器は解放する。閉じる/画面破棄/切替時にも機器を解放する。
- ファイル: 種類を限定しない選択欄を開き、選択後に対応画像/動画/音だけを検査して、種類に応じて既存の添付処理へ渡す。非対応の文書等は案内して追加しない。
- 録音: 既存のアプリ内録音・停止。音ファイルを添付し、投稿前の本文への自動文字起こしはしない。

ゲストは薄いアイコンから従来のログイン案内を開く。floor_id/room_idを保持し、ログイン後に元のルームへ戻る。ログイン機能の有効・無効は既存の環境設定に従う。

## AIタグとの関係
添付元はAIの指定ではない。アイコン操作でタグを追加/解除しない。投稿後にAI対応タグと対応メディアが揃ったとき、既存の解析処理で付加情報を生成する。文字起こし/音解析は録音・添付音・動画の音が対象。画像解析は画像、動画解析は動画。タグなしで録音を添付しただけでは解析を起動しない。

投稿・編集・返信・付加情報で入力操作を統一。代替テキスト・字幕・削除は既存MediaInputを再利用。AI解析の対象範囲（投稿/返信）は既存バックエンドに従い変更しない。

## 部品・アクセシビリティ
`MobileComposerTools`は`choose(library/camera/file)`と`record`を通知。`MediaInput.chooseSourceFile`と`handleSourceSelection`がファイル種別の検証・振り分けを担当する。`CameraCaptureDialog`は独立したフォーカス管理を持つ撮影ダイアログ。カメラを開いている間は親のCtrl+Enter送信を抑止する。録画中は停止のみ有効、キャンセルは停止後に可能。

日英名称は`composerSource`。native buttonと読み上げ名、録音/写真動画選択の押下状態、Tab/Shift+Tab/Enter/Space、閉じた時のフォーカス復帰を保持。実発話のVoiceOver検証とは分けて記録する。

## 検証
`npm run test:unit:ci -- tests/unit/components/timeline/dialogs tests/unit/components/timeline/inputs`、`npm run lint`、development build。実アプリのファイル選択/保存、PCキーボード、日英320/390px表示を確認する。撮影・録音の実機権限と実映像・音はiPhone/Androidで別確認が必要。

写真/動画に限定した入力と、汎用のファイル入力を分離する。OSが表示する選択先・メニュー順はアプリから保証できないため、iPhone/Androidで実機確認する。撮影した画像をカメラロールへ自動保存する機能やAIタグの自動選択は、この版には含めない。


## 文字数と表示

投稿・返信は400文字、付加情報本文と画像・動画・音の代替テキストは2,000 UTF-16単位。独立した音のタイトル入力は設けず、保存済みタイトルは保持する。[共通仕様](shared-alternative-text.md)に従う。

録音待機中は他の入口と同じ色、録音中だけ停止アイコン・色・押下状態で示す。撮影画面はスマホの表示領域全体、PCでは周囲16pxを残した領域に広げる。プレビューの縦横比を保ち、保存内容と異なる切り抜きをしない。写真/動画の切替と撮影操作は下部に置く。カメラロールへの自動保存とAIタグの自動選択は行わない。

新しいUI文言は日本語・英語・簡体字中国語に対応し、その他の表示言語では追加文言を英語で補う。
