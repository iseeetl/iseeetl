# タグコピー貼り付け仕様

## 概要

タイムライン上の投稿・返信に設定されたタグをアプリ内で一時コピーし、投稿・返信の作成・編集またはタグ更新へ再利用する動作を定義する。

## 動作・適用条件

### 対象範囲

#### コピー元

- タイムラインに表示されている投稿
- タイムラインに表示されている返信

#### 貼り付け先

- 投稿作成・編集ダイアログ
- 返信作成・編集ダイアログ
- タグ更新ダイアログ

本機能はOSのクリップボードへ文字列をコピーする機能ではない。ブラウザのクリップボード権限も要求しない。

### 用語と状態

| 用語 | 意味 |
| --- | --- |
| コピー済みタグ | `store.tagClipboard.list`へ一時保持したタグID配列 |
| コピー元タグ | 投稿・返信の`room_tags` |
| 選択タグ | 貼り付け先ダイアログで現在選択しているタグID配列 |
| 現在有効なルームタグ | 表示中ルームのタグ一覧に存在するタグID |

コピー済みタグは、「前回投稿」で使う持ち越しタグ（`store.tag.list`）とは別の状態である。持ち越しタグの条件は[タグの引き継ぎ仕様](tag-selection.md)を参照する。

### コピー操作

#### 表示条件

- 投稿・返信のアクション領域に、Material Iconsの`content_copy`を使ったアイコンボタンを表示する。
- タイムライン設定の「操作ボタン表示」が無効な場合はアクション領域全体を表示しないため、コピーボタンも表示しない。
- コピー元の`room_tags`が空、または現在のルームタグ一覧に存在するIDが1件もない場合は表示しない。
- コピー操作自体にログイン必須の条件はなく、アクション領域を表示できるゲストも使用できる。

#### コピー内容

1. コピー元の`room_tags`を元の順序で走査する。
2. 現在のルームタグ一覧に存在しないIDを除外する。
3. 重複IDを除外し、最初に現れた順序を維持する。
4. 結果で`store.tagClipboard.list`全体を置き換える。

- 別の投稿・返信をコピーすると、以前のコピー済みタグは上書きする。
- 有効なタグがない場合はコピーを行わず、既存のコピー済みタグも変更しない。
- コピー成功時はステータススナックバーへ「タグをコピーしました」を表示する。

#### アクセシビリティ

- アイコンボタンのアクセシビリティ名、タイトル、ツールチップは「タグのコピー」とする。
- 投稿・返信の既存アクションボタン列に配置し、デスクトップとモバイルで同じ操作を提供する。
- 画面が狭い場合も、コピーボタンを「その他」メニューなどへ移す表示切替はない。

### 貼り付け操作

#### 表示と利用条件

- 投稿・返信のタグ選択欄では、「クリア」「元投稿」「前回投稿」と同じ操作行に「貼り付け」文字ボタンを表示する。
- タグ更新ダイアログでは「クリア」と「貼り付け」を同じ操作行に置き、タグチェックボックス群を次の行に表示する。
- コピー済みタグがない場合もボタンは表示したまま無効にする。無効になっている理由は、視覚表示や支援技術で通知しない。
- コピー済みタグのうち、現在有効なルームタグが1件以上ある場合だけ有効にする。
- 投稿・返信ダイアログでは送信中または録音中、タグ更新ダイアログでは送信中も無効にする。
- 「ゲストはリアクションのみ」が有効なルームをゲストで利用する場合は投稿・返信のタグ入力欄自体を表示しないため、貼り付けボタンも表示しない。

#### 貼り付け内容

1. コピー済みタグを元の順序で走査する。
2. 現在のルームタグ一覧に存在しないIDを除外する。
3. 重複IDを除外し、最初に現れた順序を維持する。
4. ダイアログの選択タグ全体を結果で置き換える。

- 既存の選択タグへ追加する操作ではない。
- 貼り付け成功時はステータススナックバーへ「タグを貼り付けました」を表示する。
- 貼り付け操作だけではAPIを呼び出さず、`store.tag.list`も更新しない。
- その後に投稿保存が成功した場合は、投稿の持ち越しタグ更新仕様に従って`store.tag.list`を更新する。返信保存とタグ更新では更新しない。

### 状態のライフサイクル

| 契機 | コピー済みタグ |
| --- | --- |
| コピー成功 | 有効なコピー元タグで置き換える |
| 同一ページ内のダイアログ開閉 | 維持する |
| SPA内で別画面・別ルームへ移動 | 明示的には消去せず維持する |
| ページ再読み込み | 空にする |
| ログアウト | 空にする |

- `tagClipboard`はVuexルートストアにだけ保持する。
- 状態保存時は`tagClipboard`を明示的に除外し、`localStorage`の`iseeetl_store`へ永続化しない。
- 保存済み状態の読込処理も`tagClipboard`を復元しない。
- ルームリソースの初期化は持ち越しタグを消去するが、コピー済みタグは消去しない。
- 別ルームへ移動してIDが現在のルームタグ一覧と一致しなくなれば、コピー状態が残っていても貼り付けボタンは無効になる。

### 権限との関係

- コピーはデータを変更しないローカル操作であり、投稿・返信のアクション領域を表示できれば利用できる。
- 投稿・返信の作成・編集へ貼り付けられるかは、各ダイアログを開ける権限に従う。
- 専用タグ更新ダイアログはログインユーザ向けで、他者またはゲストの投稿・返信に対するタグ更新の表示条件に従う。本人分は投稿・返信編集ダイアログを使用する。
- 貼り付けは権限を追加しない。最終的な保存は対象APIの認証・認可を受ける。

### バックエンド検証との関係

- 投稿・返信の作成・更新と専用タグ更新では、送信する全タグIDが有効で、対象フロア／ルームに属するルームタグかバックエンドで検証する。
- コピー・貼り付け時にも現在のルームタグ一覧でIDを絞り込むが、これはフロントエンドの入力補助であり、バックエンド検証の代替ではない。
- 保存までにタグが削除・無効化された場合はバックエンドが拒否し、対象データを更新しない。
