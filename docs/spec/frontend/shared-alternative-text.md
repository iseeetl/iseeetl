# 共同編集の代替テキスト

画像・動画・音の説明を共通の枠組みで扱う。

## 利用者の操作

- 画像・動画・音の添付欄は共通の「代替テキスト」。最大2,000 UTF-16単位（既存の文字数カウントと同じ）。独立したタイトル入力は設けない。
- 保存済みの画像キャプションと音の説明を引き継ぐ。古い音のタイトルは消さず保持し、既存プレイヤーの名前に使用する。
- 投稿・返信・付加情報の添付メディアに対応。ルームの `collaborative_text_editing` がオンのとき、そのルームを利用できるログインユーザーが「代替テキストを追加／編集」から共同編集できる。オフでは元データの作成者と既存の管理権限者のみ。ゲストは閲覧のみ。
- 他人の本文・ファイル・タグ・投稿者情報・AIの出自はこの操作で変更できない。既存の本文編集権限はそのまま。
- 音や手話動画など、テキスト以外の代替情報は従来の付加情報として扱う。AI結果も付加情報として残し、共有の代替テキストを自動上書きしない。
- 動画の字幕添付は継続する。代替テキストは同期字幕の代わりにはしない。

## 表示設定・アクセシビリティ

タイムライン設定の「代替テキストを表示する／Show alternative text」は初期値オン。既存の付加情報表示・タグ別AI表示とは独立する。ブラウザの既存localStorage設定に保存し、全ルーム共通。設定自体はサーバーへ送らない。

オンでは添付の下に本文を表示。400文字を超えると先頭約300 Unicode文字＋省略記号を表示し「続きを読む／閉じる」で切り替える。保存値を短くしない。

オフでも「代替テキストを開く」を残す。画像のalt、メディア操作と全文のaria-describedby関連付けを維持。追加・編集・開閉はネイティブbutton、入力はlabel付きtextarea、保存状態はstatus、失敗はalert。編集ダイアログは既存のフォーカストラップを使用し、読み直し後は本文先頭へ戻す。VoiceOverの実発話の確認とは区別する。

親の付加情報自体を既存設定で隠した場合は、その添付と代替テキストも表示しない。元投稿の代替テキストは付加情報をオフにしても閲覧できる。

## APIと互換性

- `PUT /api/rooms/:room_id/timeline/posts/:post_id/alternative-text`
- 同じ末尾を `/replies/:reply_id`、`/supplements/:supplement_id`、`/replies/:reply_id/supplements/:supplement_id` に付けた計4経路。
- 入力は `{kind: image|video|audio, text, expected}` のみ。2,001文字や未知の項目を拒否。
- expectedはimage_name/video_name/audio_name/image_caption/video_description/audio_descriptionの6項目の取得時点の値。メディア・代替テキストが別途変わっていたら409。DBの条件付き更新でも一致を確認し、同時送信は片方だけ成功する。
- 通常の投稿編集も、メディアを変更するときだけ `expected_media_text` を送って古い代替テキストの上書きを防ぐ。本文だけの変更は説明を送らない。
- 既存image_caption/audio_descriptionを保存先として使い、video_descriptionを追加。構造化APIではvideo.description。データ移行や一括更新は行わない。
- 共有テキスト更新はPOST_UPDATEで同期するが、解析・翻訳・通知の再実行はしない。編集履歴や編集者表示は今回の範囲外。

## 確認

一般利用者Authorによる他人の説明編集、本文変更の403、ゲスト401、非公開ルーム・キック403、削除済み／異なるルーム404、2000許可／2001拒否、同時編集409、投稿・返信・双方の付加情報を確認する。既存タイムライン・設定保存・メディア入力の回帰試験を併用する。

ローカル専用の合成データと外部AI・翻訳・通知・GAを無効にした起動環境で実施する。PC・スマホ幅のブラウザ確認はスマホ実機、仮想キーボード、カメラ・録音、VoiceOver実発話を保証するものではない。

## ルーム別の共同編集オプション

`collaborative_text_editing` はルーム単位、初期値false。既存ルームで未設定でもfalse。既存のルーム管理権限者だけが変更できる。省略更新では保存値を維持し、真偽値以外は拒否する。

オンでは一般ログインユーザーが他人の代替テキストと、人・AIの付加情報の本文を編集できる。ゲストは不可。付加情報は最大2,000文字の本文だけを扱う専用APIで、作成者・タイトル・AIの出自・添付ファイルを変更できない。削除や既存の本文編集APIの権限は広げない。付加情報の原文と言語を読み込み、その原文の言語で訂正する。古い翻訳を消し、翻訳機能が有効な環境では訂正した本文を再翻訳する。翻訳結果も本文・言語の一致を確認して保存する。

- `PUT /api/rooms/:room_id/timeline/posts/:post_id/supplements/:supplement_id/text`
- `PUT /api/rooms/:room_id/timeline/posts/:post_id/replies/:reply_id/supplements/:supplement_id/text`
- 本文 `{text,lang,expected:{content,lang}}`。ゲスト401、権限不足403、削除済み404、競合409、上限超過・未知キー400。
- ルームを移動するたびに許可状態を読み直す。保存時はサーバーでも再判定する。開いた後に許可が外れた場合は保存を拒否する。
- オフに戻しても保存済みの編集は戻らない。既存の自分の情報と管理者の編集権限は維持。
- 編集は既存の鉛筆アイコンと同じ外観、名前は「代替テキストを編集」「付加情報の文章を編集」。今回フロア単位の新しい編集者権限と履歴復元は追加しない。
- 共同編集を試すルームだけ管理画面でオンにする。ほかのルームには適用しない。

## 旧版へ戻す場合

DBを一括変換せず、既存フィールドと追加フィールドで保存する。ソース・配布物の復元は、共同編集された本文そのものを以前の文章へ戻す操作ではない。旧版では動画の代替テキストや新しいリアクションの操作は利用できず、長い代替テキストの再編集にも旧上限が適用される。復元前に現在データを保全し、旧版での読取・通常更新の互換性を確認する。削除や投稿全体の置換まで、あらゆる操作の互換性を保証するものではない。編集履歴の復元はこの機能に含まない。
