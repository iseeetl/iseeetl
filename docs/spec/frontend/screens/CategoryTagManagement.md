# 共通タグ管理（/management/categorytag）

## 概要

- 新しいフロアへコピーする共通タグ（`CategoryTag`）を管理する
- 共通タグの作成、編集、削除、CSVによる一括同期・出力を行う
- 共通タグの変更は既存フロア／ルームへ自動同期せず、変更後に作成するフロアの初期データへ反映される

## 利用条件・開き方

- 入口はアプリメニューの管理者向け「共通タグ管理」、またはURLへの直接アクセスである

### URL

| 項目 | 値 |
| --- | --- |
| パス | `/management/categorytag` |
| ルート名 | `CategoryTagManagement` |
| コンポーネント | `frontend/src/views/management/CategoryTagManagement.vue` |
| メタ情報 | `isManagement: true` |

- アプリメニューはVuex上のロールが`Administrator`の場合だけ「共通タグ管理」を表示する
- ルートガードは遷移時にlocalStorageから状態を復元し、ログイン済みAdministratorだけを通過させる
- 未ログインまたはAdministrator以外が直接アクセスした場合はログアウト処理を行い、`/login`へ遷移する
- ルートメタ情報に画面タイトルはなく、文書タイトルにはアプリ名だけを設定する

### 利用条件

| 利用者 | アプリメニュー | 画面遷移 | バックエンドAPI |
| --- | --- | --- | --- |
| Administrator | 表示 | 可 | 可 |
| Editor／Author／developer | 非表示 | ログアウト後ログイン画面へ遷移 | 403 |
| ゲスト | 非表示 | ログイン画面へ遷移 | 401 |

- バックエンドはすべての共通タグAPIでJWTとサイト管理者ロールをミドルウェアで確認する
- 作成者は`user`として保存するが、編集・削除は作成者本人に限定せず、現在のAdministratorなら実行できる
- 詳細なAPI契約は[共通タグAPI](../../backend/api/category-tag.md)を参照する

## 画面構成

- H1「共通タグ管理」
- タイトル行右端の「作成」ボタン
- 枠付きの「CSV入出力」領域。ブラウザ標準のファイル入力欄は非表示にし、塗りつぶしの「CSVをインポート」「CSVをエクスポート」ボタンを表示する
- CSVインポートのプレビューダイアログ
- 検索欄
- 一覧テーブル
  - 表示順番
  - タグ名
  - 作成日
  - 更新日
  - 操作
- 作成時は「共通タグ - 作成」、編集時は「共通タグ - 編集」と区別する作成・編集ダイアログ。編集時だけ保存済み対象タグ名を入力欄より先に表示する
- 共通の一覧状態・ページャと、保存・CSV処理のエラー／完了通知用スナックバー

## 操作と動作

### タグの継承と同期範囲

```text
CategoryTag（この画面）
  └─ Floor作成時に有効タグをFloorTagへコピー・翻訳
       └─ Room作成時に有効タグをRoomTagへコピー・再翻訳
```

- フロア作成時は、その時点で`delete_flg=false`の共通タグについて、表示順、名前をフロアタグへコピーする
- 共通タグは原文言語を持たないため日本語を原文として扱い、フロアの翻訳対象言語に合わせてフロアタグの翻訳を新規作成する
- 作成済みフロアタグ／ルームタグは別データであり、この画面での作成・編集・削除やCSVインポートには追随しない
- フロアタグに保存された`source_category_tag`はコピーの履歴である。共通タグを物理削除しても既存フロアタグを連鎖削除せず、来歴IDも維持する
- 既存フロアへ共通タグを再適用する`POST /api/floortag/init`は、フロア側のタグ管理機能であり、この画面には実行導線がない
- タグの所有関係と同期方式は[ドメインモデル](../../domain-model.md)を参照する

### 初期表示・一覧・検索・ページング

- 一覧の共通状態、検索フォーム、ページャ、URL履歴、競合要求、ページ補正は[管理一覧・検索共通仕様](../management-list.md)に従う
- 初期表示は`GET /api/categorytag/management/paginate?page=1&search=`を呼び出し、有効なタグだけを取得する。旧論理削除データは表示せず、自動復元しない
- 1ページ10件で、共通タグを`order`昇順で表示する
- 検索はタグの原文名を対象とする、大文字・小文字を区別しない部分一致である
- バックエンドは検索文字列の前後空白を除去し、正規表現の特殊文字をリテラルとして扱う
- 検索文字列は任意で最大50文字

### 作成・編集・削除

- 「作成」は空の「共通タグ - 作成」ダイアログを開く。有効な行の明示的な「編集」は選択タグの値を設定して「共通タグ - 編集」ダイアログを開く。行全体は操作対象にしない
- 編集時の対象タグは一覧行の保存済み名称を表示し、入力欄でタグ名を変更しても対象表示はダイアログを開いた時点の名称を維持する
- 入力項目は表示順番とタグ名で、論理削除チェックボックスは表示しない
- 表示順番は1〜100の整数とし、未入力時は100を補完する
- タグ名は必須、最大50文字で、バックエンド保存前に前後空白を除去する
- 新規は`POST /api/categorytag/management/create`、既存の内容編集は`POST /api/categorytag/management/update`を使用する
- 各行は「削除」「編集」の順で操作を表示する。対象名と元に戻せないことを示す確認ダイアログの後、`POST /api/categorytag/management/delete`へ`_id`だけを送る。タグを物理削除し、復元操作は提供しない
- 有効な共通AI解析設定から直接参照中の共通タグは削除できず、バックエンドは409と`ACTIVE_AI_ANALYSIS_REFERENCE`理由を返す。画面は「削除に失敗しました」に「有効なAI解析設定で使用されているため削除できません。先に関連するAI解析設定を削除してください」を連結し、対象と確認ダイアログを維持する
- 有効なフロアタグの`source_category_tag`から参照されていることだけでは削除を拒否しない。削除後もフロアタグと来歴IDを維持するが、この来歴はフロアAI解析設定の作成・編集・削除の条件には使用しない
- 保存、削除の成功後は現在ページを再取得してダイアログを閉じる。削除の送信中と再取得中は対象を維持し、失敗時はダイアログを開いたまま再操作可能にする
- PCでは右下に「キャンセル」と「作成」または「保存」を隣接配置し、スマートフォンではヘッダー左の取消しと右の確定を使用する
- 未変更の取消し、Escape、外側クリックは直ちに閉じる。表示順番またはタグ名に未保存変更がある場合は破棄確認を表示し、確認の取消しでは入力へ戻り、破棄の確定では保存せず閉じる
- 保存中は入力と操作を無効化し、共通の処理中表示を出す

### CSVインポート

- `.csv`ファイルをブラウザでUTF-8テキストとして読み、先頭BOMを除去して検証する
- 1行は`order,name`の2列で、`order`は1〜100、`name`は1〜50文字とする
- 名前はダブルクォートで囲め、名前内のカンマと二重化したダブルクォートを扱える。ヘッダ行は使用しない
- カンマを含まない行は読み飛ばし、カンマを含む不正形式行が1行でもあればファイル全体をエラーにする
- バックエンドは1〜100行だけを受け付け、同じファイル内または既存の有効タグ内に完全一致する重複名があれば、同期開始前に400とする
- 有効タグの名前の完全一致を同一タグとして、既存IDを維持したまま順番を更新する。旧論理削除タグと同名の場合は新しいIDで作成する
- ファイルにない有効タグは、有効な共通AI解析設定から直接参照されていない場合に物理削除し、新しい名前は新規作成する。削除対象に直接参照中のタグが1件でもあればバックエンドは409として同期全体を拒否する。フロアタグの来歴参照は拒否条件にせず、子タグの連鎖削除は行わない
- ファイル選択時はすぐに送信せず、件数、ファイル名、現在の共通タグを置き換え、元に戻せないことを示す警告を`ConfirmDialog`のプレビューに表示する。明示的な実行または取消しで確定する
- 送信中はプレビューと対象ファイルを維持する。成功時は1ページ目から再取得し、完了通知後にプレビューを閉じる。失敗時はプレビューを維持して再試行できる

### CSVエクスポート

- `POST /api/categorytag/management`で論理削除されていないタグだけを全件取得する
- 表示順、同順の場合は名前で並べ、`order,name`形式の`categorytag.csv`を出力する
- 改行はCRLF、文字コード判別用にUTF-8 BOMを付け、カンマ・改行・ダブルクォートを含む名前をCSVエスケープする
- エクスポート中は「CSVをエクスポート」を無効化し、完了後にObject URLを破棄する

## 通信・エラー時の動作

- CSV同期はMongoDBトランザクションを使用しないため、書込み途中のDBエラーで部分更新され得る

### 使用するAPI

| 目的 | Method / Path | 主な送信値 | 画面での扱い |
| --- | --- | --- | --- |
| ページング一覧 | `GET /api/categorytag/management/paginate` | クエリ: `page`, `search` | `docs`, `page`, `pages`, `total`を一覧状態へ反映 |
| 作成 | `POST /api/categorytag/management/create` | `order`, `name` | 成功後に現在ページを再取得 |
| 更新 | `POST /api/categorytag/management/update` | `_id`, `order`, `name` | 成功後に現在ページを再取得 |
| 削除 | `POST /api/categorytag/management/delete` | `_id` | 物理削除し、成功後に現在ページを再取得 |
| CSV同期 | `POST /api/categorytag/management/import` | `csv` | 成功後に1ページ目を再取得 |
| CSV出力用一覧 | `POST /api/categorytag/management` | なし | 画面内でCSVへ変換してダウンロード |

- ページングルートは共通処理関数をGET／POSTの両方へ登録しているが、現行フロントエンドはGETを使用する
- APIエラーは処理別の文言と安全な利用者向け詳細をスナックバーへ表示する。削除の失敗には「削除に失敗しました」を使用する
- 一覧取得で401となった場合はログアウトしてログイン画面へ遷移する

### 読み込み中・データなし・エラー時

- 初回読込、更新中、空、取得失敗、前回結果を保った失敗、再試行は[管理一覧・検索共通仕様](../management-list.md)に従う
- 一覧取得の失敗は画面内に表示し、保存・CSV処理の失敗はスナックバーで通知する
- CSVファイルの形式エラー、読込エラーは通知して入力をクリアする。API エラーではプレビューを維持し、プレビューを閉じたときに入力をクリアする
