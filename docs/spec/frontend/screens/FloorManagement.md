# フロア管理（/management/floor）

## 概要

- 全フロアをサイト管理者が横断参照し、既存フロアの内容、翻訳対象言語、画像、一覧表示状態を更新する
- 論理削除状態は状態絞り込み条件で参照範囲を切り替え、行の明示的な削除・復元操作で変更する
- この管理画面は既存フロアの更新専用であり、フロアの新規作成や物理削除は行わない

## 利用条件・開き方

- 入口はアプリメニューの管理者向け「フロア管理」、またはURLへの直接アクセスである

### URL

| 項目 | 値 |
| --- | --- |
| パス | `/management/floor` |
| ルート名 | `FloorManagement` |
| コンポーネント | `frontend/src/views/management/FloorManagement.vue` |
| メタ情報 | `isManagement: true` |

- アプリメニューはVuex上のロールが`Administrator`の場合だけ「フロア管理」を表示する
- ルートガードは遷移時にlocalStorageから状態を復元し、ログイン済みAdministratorだけを通過させる
- 未ログインまたはAdministrator以外が直接アクセスした場合はログアウト処理を行い、`/login`へ遷移する
- ルートメタ情報に画面タイトルはなく、文書タイトルにはアプリ名だけを設定する

### 利用条件

| 利用者 | アプリメニュー | 画面遷移 | バックエンド管理API |
| --- | --- | --- | --- |
| Administrator | 表示 | 可 | 可 |
| Editor／Author／developer | 非表示 | ログアウト後ログイン画面へ遷移 | 403 |
| ゲスト | 非表示 | ログイン画面へ遷移 | 401 |

- バックエンドはJWTとサイト管理者ロールをミドルウェアで確認し、サービスでもJWTのユーザ IDから有効なAdministratorを再確認する
- 現在のAdministratorは作成者本人かどうかにかかわらず、論理削除済みを含む全フロアを更新できる
- 通常のフロア画面で更新できるのはAdministrator、または現在ロールが`Editor`である対象フロア作成者であり、この画面は全体管理用の別経路である
- 詳細なAPI契約は[フロア API](../../backend/api/floor.md)、通常画面の挙動は[フロア画面仕様](Floor.md)を参照する

## 画面構成

- H1「フロア管理」
- ラベル「検索する」の検索欄
- 状態絞り込み条件（すべて／未削除／削除済み）
- 全フロアを横断する一覧テーブル
  - タイトル
  - 作成ユーザ名
  - 作成日
  - 更新日
  - 削除日
  - 状態（有効／削除済み、表示／非表示）
  - 操作
- 通常のフロア一覧と同じタイトル、対象表示、入力区分、操作配置を使用し、`EditFloorDialog`を管理モードで使用する編集ダイアログ
- 共通の一覧状態・ページャと、編集結果用の共通ストアスナックバー
- 作成ボタン、作成者・表示状態による絞り込み、物理削除操作はない

## 操作と動作

### 初期表示・一覧・検索・ページング

- 一覧の共通状態、検索フォーム、ページャ、URL履歴、競合要求、ページ補正は[管理一覧・検索共通仕様](../management-list.md)に従う
- 初期表示は`GET /api/floor/management/paginate?page=1&search=`を呼び出し、未削除と削除済みを取得する
- 1ページ10件で、フロアを`created_at`降順で表示する。状態の絞り込みは共通仕様に従う
- バックエンドは作成ユーザの`username`をpopulateし、一覧の「ユーザ名」へ表示する
- 表示／非表示は状態欄に表示する。説明、原文言語、翻訳対象言語、画像の有無は一覧へ表示しない
- 検索は原文のタイトルまたは説明を対象とする、大文字・小文字を区別しない部分一致である
- バックエンドは正規表現の特殊文字をリテラルとして扱うが、検索文字列の前後空白は除去しない
- フロントエンドは2〜10文字を入力条件とし、範囲外の検索要求を送らない。バックエンドの上限は100文字で、空検索は`search=`で送る

### 編集ダイアログ

- 有効な行の明示的な「編集」で、選択フロアの値を設定して「フロアを編集」ダイアログを開く。行全体は操作対象にしない
- 見出し直後に「対象フロア」と変更前のフロア名を表示し、ダイアログの説明として関連付ける
- 入力は「基本情報」「画像」「表示・通知」の3区分とする。PCでは共通幅480pxでキャンセルと保存を右側へ隣接し、スマートフォンでは左右の上部操作へ切り替える
- 入力・操作項目は次のとおりである
  - タイトル: 必須、最大100文字
  - 説明: `null`または最大200文字
  - 自動翻訳の対象言語: Google Translateが利用可能な場合だけ表示する、対応言語のチェックボックス
  - フロア画像の選択、選択取消、登録済み画像の削除
  - `floor_display_hidden`: 「非表示にする」
- この管理画面からは`showLifecycleControl=false`を渡し、編集ダイアログ内に論理削除チェックボックスを表示しない。編集ペイロードは対象の元の`delete_flg`を維持する
- 原文言語の選択欄はなく、既存の`lang`を維持する。未設定の場合は`ja`として保存する
- Google Translateが利用不可の場合は翻訳対象言語を表示せず、保存済み`target_langs`を保持する
- 管理モードでの確定には一覧から渡された既存フロアの`_id`を必須とする。対象IDがない状態で確定しても、画像アップロード、作成、更新、成功通知を行わない
- 入力、翻訳対象、画像、表示状態を変更してからキャンセル、Escape、外側クリックを行うと破棄確認を表示する。変更していない場合と開始状態へ戻した場合は確認せず閉じる
- 保存成功後はダイアログ状態を初期化し、同じページと検索条件で一覧を再取得する
- 保存中は主要入力、画像削除、表示チェック、キャンセル、保存、Escape、外側クリックを抑止し、進捗バーを表示する

### 翻訳と下位データへの影響

- Google Translateが利用可能で、タイトル、説明、原文言語、対象言語のいずれかが変化した場合はフロアのタイトル・説明の翻訳を再生成する
- Google Translateが利用可能で、対象言語の集合が変化した場合だけ、論理削除されていないフロアタグ／ルームタグと、対象フロアの全フロア／ルーム単語グループ・項目、配下の全ルームの翻訳を再生成する
- タイトル・説明だけを変更した場合はフロアタグ、フロア単語、ルーム、ルームタグ、ルーム単語を再翻訳しない
- Google Translateが利用不可の場合は外部翻訳を行わず、保存済みの翻訳対象言語と翻訳結果を機能OFFだけを理由に消去しない

### 非表示・論理削除・復元

- `floor_display_hidden`は通常一覧での表示範囲を制御するが、この管理一覧には影響しない
- 有効な行は削除、編集の順、削除済み行は復元だけを表示する。対象名と復元可能であることを示す確認ダイアログの後、状態専用APIへ`_id`と`delete_flg`だけを送る
- `delete_flg=true`では`deleted_at`を現在日時へ設定し、`false`では`deleted_at=null`としてフロアだけを復元する。確認ダイアログの状態と再取得は[共通仕様](../management-list.md#論理削除復元の確認)に従う
- 有効なフロア／ルームAI解析設定が存在してもフロアを削除できる。フロアの論理削除・復元は配下のルーム、フロアタグ、フロア単語、フロア／ルームAI解析設定、メンバー、投稿、メディアの削除状態を変更しない
- フロアが論理削除中は配下のAI解析設定を利用できない。復元後は配下データとAI解析設定がそれぞれの既存状態を維持し、有効なものを再び利用できる。削除済みの子データを自動復元しない
- 論理削除への変更成功後は対象フロアの全Socketへ`ACCESS_REVOKED`（`floor_deleted`）を通知して切断する。対象タイムラインはログイン状態を維持してフロア一覧へ遷移する
- 復元・非表示・翻訳対象言語の変更では接続を切断しない。製品内の操作履歴は記録しない

### 画像処理と保存順序

- フロントエンドはJPEG／PNGを受け付け、選択画像を最大幅800px、品質0.8のJPEG Blobへ変換し、変換後3MB以下を確認する
- バックエンドは画像署名、実形式、デコード可否、画素数などを再検査し、メタデータを引き継がず公開領域へ再エンコードする
- 新画像がある場合は、先に`POST /api/fileupload/floor/image`で保存し、その画像名を管理更新APIへ送る
- 画像名が変化した場合はフロアのDB更新後に旧画像を削除し、削除に失敗しても更新は成功し、ファイルが残る場合がある
- 登録済み画像の削除は`image_name=null`を管理更新APIへ送り、DB更新後に旧画像ファイルを削除する
- 保存済み画像と選択中画像の分離、取消・削除、同じファイルの再選択、保存失敗時の状態は[保存済み画像の差し替えと取消](../media-input.md#保存済み画像の差し替えと取消)に従う
- 画像の共通契約は[メディア入力制約](../media-input.md)と[ファイルアップロードAPI](../../backend/api/upload.md)を参照する

## 通信・エラー時の動作

- 対象言語変更後のフロア本体、フロアタグ、フロア単語、ルーム、ルームタグ、ルーム単語再翻訳は非トランザクションであり、途中失敗時に翻訳対象が部分更新される
- 画像アップロード後に管理更新が失敗すると、未参照画像が残る

### 使用するAPI

| 目的 | Method / Path | 主な送信値 | 画面での扱い |
| --- | --- | --- | --- |
| ページング一覧 | `GET /api/floor/management/paginate` | クエリ: `page`, `search`, 任意 `delete_flg` | `docs`とページ情報を反映 |
| フロア画像保存 | `POST /api/fileupload/floor/image` | multipart: `_id`, `image_file` | 新画像がある場合だけ管理更新より先に実行 |
| 更新 | `POST /api/floor/management/update` | `_id`, `title`, `description`, `lang`, `target_langs`, `image_name`, `floor_display_hidden`, 元の`delete_flg` | 成功後に現在ページを再取得 |
| 削除・復元 | `POST /api/floor/management/delete-state` | `_id`, `delete_flg` | 状態だけを変更し、成功後に現在ページを再取得 |

- ページングルートはGET/POSTの両方を受け付けるが、現行フロントエンドはGETを使用する
- `/api/floor/management/create`はバックエンドに存在せず、この画面にも作成導線はない。フロントエンドのフロア create アダプタも通常の`/api/floor/create`だけを使用する
- 401ではログアウトしてログイン画面へ遷移し、それ以外の失敗は処理別文言とAPIエラーコードに対応する翻訳済みの詳細をスナックバーへ表示する

### 読み込み中・データなし・エラー時

- 初回読込、更新中、空、取得失敗、前回結果を保った失敗、再試行は[管理一覧・検索共通仕様](../management-list.md)に従う
- 一覧取得の失敗は画面内に表示し、更新・画像処理の失敗は共通ストアのスナックバーで通知する
- フロア本体のDB更新後に下位データの再翻訳が失敗した場合、失敗表示時でもフロア本体は更新済みの場合がある
