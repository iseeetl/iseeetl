# プロフィールダイアログ

## 概要

- ログイン中ユーザのプロフィール、言語、目にやさしいモード、Webプッシュ通知設定を確認・更新する
- アプリメニューとヘッダーから開く場合はURLを変更せず、現在画面の上に共通のプロフィールダイアログを表示する

## 利用条件・開き方

- アプリメニューの「プロフィール」、またはヘッダーのプロフィール画像（画像未設定時は人物アイコン）
- アプリメニューの入口はログイン中だけ表示する

### 表示方式

- 独立したルートと画面URLは持たない
- `frontend/src/App.vue`が共通の`ProfileDialog`を1つマウントし、メニューとヘッダーの入口から表示状態を切り替える

### 利用条件

- JWTを持つログインユーザ本人だけが利用できる。未ログイン時はメニューとヘッダーに入口を表示しない
- Administrator、Editor、Author、developerのロール差、フロアメンバー／ルームメンバー、キック状態、フロア／ルーム設定による利用制限はない
- 現在ロールが`Editor`の場合だけ、「権限」「フロア編集者」をダイアログ内へ表示する。この表示は保存権限を追加しない

## 画面構成

- 共通編集ダイアログのタイトル「プロフィール」
- 通信中に表示する進捗率を示すバー
- ユーザ名、現在のアイコン、新しいアイコンの選択・プレビュー・削除
- `LanguageSelector`による表示言語選択
- 目にやさしいモード
- OneSignalのWebプッシュ通知が利用可能な場合だけ、Webプッシュ通知の開始／停止、自分の投稿への返信通知、自分が返信した投稿への新返信通知
- ChangePasswordへ進む「パスワード変更」と、プロフィールを破棄して閉じる「キャンセル」、プロフィールを保存する「保存」
- PCでは画面中央のダイアログとして表示し、本文だけをスクロール可能にしてフッターの操作を固定する
- モバイルではほぼ全画面で表示し、ヘッダー左側の閉じる操作と右側の保存操作を使用する

## 操作と動作

### 初期表示

- ダイアログを開くたびに`GET /api/user/detail`を実行し、ユーザ名、アイコン名、言語、目にやさしいモード、3種類の通知設定をフォームへ反映する。前回閉じたときの未保存状態は再利用しない
- 言語が未設定の場合はVuexに保持している言語を使用し、画面表示中の`$i18n.locale`へ即時反映する
- 設定値がない場合、目にやさしいモードとWebプッシュは`false`、2種類の返信通知は`true`を既定値とする
- OneSignalのWebプッシュ通知が利用可能な場合は現在のPush Subscription状態を取得し、`push_enabled`よりブラウザの購読状態を優先して表示する
- OneSignalのWebプッシュ通知が利用可能でSDK初期化の完了待ちの場合は`window.OneSignalDeferred`へ同期処理を登録する。SDKが利用できない間も、通知ボタン以外のプロフィール操作は継続できる
- OneSignalのWebプッシュ通知が無効な場合はPush設定fieldsetを表示せず、SDK参照、Deferred登録、変更イベントリスナー登録を行わない。バックエンドから取得した3種類のPush設定値はフォーム内で保持する
- 初期取得に失敗した場合もダイアログを閉じず、エラー表示から再試行できる

### アイコン

- 「アイコンにする画像」の画像アイコンボタンからファイル選択を開く。選択取消・保存済みアイコン削除後は、このボタンへフォーカスを戻す

- 保存済み画像と選択中画像の分離、取消・削除、同じファイルの再選択、保存失敗時の状態は[保存済み画像の差し替えと取消](../media-input.md#保存済み画像の差し替えと取消)に従う
- 保存済みアイコンの削除操作は「アイコンを削除する」、選択中画像の取消操作は「アイコンにする画像・キャンセル」とする

### 言語と目にやさしいモード

- 言語選択は画面の翻訳言語へ即時反映するが、ユーザ情報への保存は「保存」時に行う
- アプリメニューまたはヘッダーのどちらから開いた場合も、キャンセル、Esc、背景クリック、モバイルヘッダーから保存せずに閉じることを確定すると、ダイアログを開いた時点の言語へ戻す
- 保存成功時はVuexと`$i18n.locale`を更新し、その言語を新しい確定値とする
- 保存成功時は、表示中の自分のユーザ名とアイコンも最新値へ更新する。アイコンを削除した場合は既定の代替表示へ切り替える
- 目にやさしいモードはタイムライン表示時に文字サイズを20pxへ上書きし、テキストアニメーションを停止する
- タイムラインを開いたまま保存した場合は、確定した言語でフロア／ルーム表示と翻訳対象を更新し、Socketを再接続する。目にやさしいモードも表示中のタイムラインへ即時反映する
- ルーム一覧を開いたまま言語を変更した場合は、フロア名・説明と各ダイアログに渡す対象名も現在言語で再計算する
- タイムラインURLに有効な`lang`または`eyeFriendlyMode=on`がある場合はURL指定を優先し、プロフィールの取得・選択・保存で一時表示を上書きしない

### Webプッシュ通知

- この節の操作はOneSignalのWebプッシュ通知が利用可能な場合だけ画面へ表示する
- OneSignalのPush Subscriptionに対して`optIn`／`optOut`を実行する
- 通知権限がない状態で開始する場合はブラウザの通知許可を要求し、拒否された場合は購読状態を変更しない
- OneSignalの初期化が完了していない場合はAPIを呼ばず、時間を置いて再試行するようalertで通知する
- 購読状態の変更に成功すると、「保存」を押さなくてもプロフィール更新を自動実行し、`push_enabled`を保存する。この自動更新ペイロードは最後に取得または保存に成功した値を使用し、ダイアログ内の未保存ユーザ名、言語、アイコン、表示・返信通知設定を保存しない
- 2種類の返信通知チェックボックスはWebプッシュ購読中だけ操作でき、変更内容は「保存」で保存する
- OneSignalのSubscription／Permission変更イベントをダイアログ状態へ反映し、ダイアログを閉じた時点でイベントリスナーを解除する。遅延初期化コールバックも閉じたダイアログを更新しない

### 保存、取消、画面遷移

- 新しい画像がなければ`POST /api/user/update`だけを実行する
- 新しい画像があれば`POST /api/fileupload/profile/image`、`POST /api/user/update`の順に実行する
- 更新ペイロードは`username`、`image_name`、`lang`、`eye_friendly_mode`、`push_enabled`、`reply_push_enabled`、`replied_post_push_enabled`である
- OneSignalのWebプッシュ通知が無効な場合も、バックエンドから取得した3種類のPush設定値を通常のプロフィール更新ペイロードへ含め、機能OFFだけを理由に値を初期化しない
- 更新成功時はレスポンスをフォームとVuexのプロフィール状態へ反映し、画像選択と入力検証状態を初期化して、成功スナックバーを表示した後にダイアログを閉じる
- 入力に未保存変更がある状態で閉じようとした場合は、破棄確認を表示する。破棄しない場合はダイアログへ戻り、破棄する場合は開く前の言語へ戻して閉じる
- 送信中は閉じる操作を受け付けない
- アプリメニューまたはヘッダーから開いたダイアログを閉じても、背後のルートとURLは変更しない
- プロフィールの開始と通常終了では、プロフィールと背面の滞在区間を分けて計測する。パスワード変更では背面ページの計測を挟まない。送信順序は[ルーティング](../routing.md#google-analyticsのページ計測)に従う
- 「パスワード変更」はプロフィールダイアログを閉じてから`ChangePassword`へ遷移する。プロフィールの未保存入力は保存しない。遷移が予期せず失敗した場合は元画面に留まり、保留したAnalyticsの背面コンテキストを復元する

## 入力条件

### ユーザ名

- フロントエンド: 必須、20文字以下。入力値の前後空白は除去しない
- バックエンド: 必須の文字列、空文字不可、20文字以下
- blurまたは保存時にVuelidateを更新し、項目エラーを`role="alert"`で表示する
- 保存時の入力検証に失敗した場合は、APIを呼ばず「入力を確認してください」をalertのスナックバーで表示する

### プロフィール画像

- ファイル選択で受け付ける申告MIMEは`image/png`、`image/jpg`、`image/jpeg`である
- フロントエンドは選択画像を中央基準の正方形へ切り抜き、200×200、品質0.5のJPEG Blobとプレビュー用Data URLへ変換する
- フロントエンドの3MB上限は、元ファイルではなく変換後Blobに対して確認する
- アップロード時は変換後Blobを`image_file`、ファイル名`image.jpg`として送信する
- バックエンドは3MB以下の申告MIMEに加え、PNG／JPEG署名、実形式、デコード可否、縦横、展開後40,000,000画素以下を検査し、メタデータを引き継がず再エンコードする
- 不正種別、上限超過、画像処理失敗はalertのスナックバーで通知し、プロフィール更新を開始しない

## 通信・エラー時の動作

- 新しい画像のアップロードとプロフィール更新は別APIである
- OneSignalの購読変更と`push_enabled`保存は別処理である

### 使用するAPI

| 用途 | Method / Path | 主な結果 |
| --- | --- | --- |
| 本人情報の取得 | `GET /api/user/detail` | 現在のプロフィール・表示・通知設定 |
| プロフィール画像の保存 | `POST /api/fileupload/profile/image` | サーバ生成の`image_name` |
| 本人情報の更新 | `POST /api/user/update` | 更新後のプロフィール・表示・通知設定 |

- 全APIでJWTが必要である
- プロフィール更新で画像名を変更または`null`にすると、DB更新後に以前の物理画像を削除する。削除に失敗しても更新は成功し、ファイルが残る場合がある
- 認証エラーの401では共通APIクライアントと画面側の認証エラー処理によりログアウトし、ログイン画面へ遷移する

### 読み込み中・データなし・エラー時

- 初期取得中はダイアログ内に読み込み中状態を表示し、編集・保存を開始できない
- `sending=true`中は進捗バーを表示し、画像選択と閉じる操作を無効化する。保存メソッドは実行中の再送を抑止する
- 画像アップロードまたはプロフィール更新の送信済み割合を整数のパーセントで表示し、完了・失敗時に0へ戻す
- 初期取得、画像アップロード、プロフィール更新、OneSignal操作の失敗は、処理別の文言へAPIエラー詳細を追記してalertのスナックバーで通知する
- 初期取得に失敗した場合は編集フォームを表示せず、エラー状態と再試行操作を表示する
- 画像アップロードまたはプロフィール更新に失敗した場合、保存済みアイコンと選択中のプレビューを維持して再操作できる
