# 共通の単語管理（/management/quicktext）

## 概要

- 新しいフロアへコピーする共通単語を、グループと項目の2階層で管理する
- グループ・項目の作成、編集、物理削除、表示順の変更を行う
- この画面の変更は既存フロア／ルームへ同期せず、変更後に作成するフロアの初期データへ反映される

## 利用条件・開き方

- 入口はアプリメニューの管理者向け「単語管理」、またはURLへの直接アクセスである

### URL

| 項目 | 値 |
| --- | --- |
| パス | `/management/quicktext` |
| ルート名 | `QuickTextManagement` |
| コンポーネント | `frontend/src/views/management/QuickTextManagement.vue` |
| メタ情報 | `isManagement: true` |

- アプリメニューの「単語管理」はVuex上のロールが`Administrator`の場合だけ表示する
- ルートガードは遷移時にlocalStorageから状態を復元し、ログイン済みAdministratorだけを通過させる
- 未ログインまたはAdministrator以外が直接アクセスした場合はログアウト処理を行い、`/login`へ遷移する
- ルートメタ情報に画面タイトルはなく、文書タイトルにはアプリ名だけを設定する

### 利用条件

| 利用者 | アプリメニュー | 画面遷移 | バックエンドAPI |
| --- | --- | --- | --- |
| Administrator | 表示 | 可 | 可 |
| Editor／Author／developer | 非表示 | ログアウト後ログイン画面へ遷移 | 403 |
| ゲスト | 非表示 | ログイン画面へ遷移 | 401 |

- 画面の`created`でも現在ロールを確認し、Administratorの場合だけ初期取得する
- グループ作成ボタンもAdministratorの場合だけ表示する
- バックエンドはJWT上の管理者ロールをミドルウェアで確認した後、サービスでもJWTのユーザIDから有効なユーザを再取得し、DB上の現在ロールがAdministratorであることを再確認する
- グループ作成者は`user`として保存するが、更新・削除は作成者本人に限定せず、現在のAdministratorなら実行できる

## 画面構成

- H1「単語管理」
- 「単語グループ作成」ボタン
- ドラッグ可能な全グループ一覧
  - 原文タイトル
  - 表示順番
  - 原文言語
  - 非ボタン要素のドラッグハンドル
  - 項目作成
  - グループ削除、グループ編集の行操作
- 各グループ内のドラッグ可能な項目一覧
  - 原文ラベル
  - 表示順番
  - 原文言語
  - 非ボタン要素のドラッグハンドル
  - 項目削除、項目編集の行操作
- グループ／項目の編集ダイアログと削除確認ダイアログ
- 共通の単語は翻訳配列を持たないため、フロア／ルーム単語画面のような翻訳チップは表示しない
- ページャや検索UIはなく、管理用グループとその全項目を1画面へ表示する

## 操作と動作

### 初期表示・一覧取得

- Administratorでログイン中かつ別処理中でない場合だけ、全件取得APIでグループを取得する
- グループ取得中はstatusを、0件は専用の空状態を表示する。取得失敗はalertと「再試行」ボタンを画面内に表示する
- 全グループを`order`、`created_at`、`_id`の昇順で取得した後、各グループの項目を`Promise.all`で並行取得する
- 項目もグループごとに`order`、`created_at`、`_id`の昇順で表示する
- 各グループの項目取得は個別の読込中、空、エラーを表示し、失敗したグループだけを再試行できる
- グループ保存後はグループ全件と全グループの項目を再取得する
- 項目保存または削除後は対象グループの項目だけを再取得する
- グループ削除後は画面内の対象グループと対応する項目キャッシュを除去し、全件再取得は行わない

### グループ／項目の作成・編集

- グループはタイトル、項目はラベルだけを入力する
- グループ編集では「単語グループ名」に変更前のタイトルを表示する。項目の作成・編集では「単語グループ名」に追加先を表示し、項目編集ではさらに「名称」に変更前のラベルを表示する
- 作成の確定操作は「作成」、編集の確定操作は「保存」、終了操作は「キャンセル」とする。PCでは右下へ隣接し、モバイルではヘッダー左のキャンセルと右の確定操作へ切り替える
- 開始時からタイトルまたはラベルを変更してキャンセル、Escape、外側クリックを行うと破棄確認を表示する。変更していない場合と開始状態へ戻した場合は確認せず閉じる
- 作成時の表示順番は、グループ全体または同一グループ内項目の最大`order + 1`としてバックエンドが自動採番する
- フロントエンドから作成時の`order`は送らず、バックエンドも受け取った`order`を採番には使用しない
- 保存中は対象ダイアログの入力、閉じる、再送信を抑止し、完了率を示さない進捗バーを表示する
- 保存成功後はダイアログを閉じ、対象一覧を再取得して成功スナックバーを表示する
- 保存失敗時はダイアログを維持し、処理別文言とAPIエラー詳細を括弧付きで表示する

### 削除

- グループ削除では、「単語グループ名」に対象タイトルを独立表示し、「配下単語も削除されます」という確認を表示する
- 項目削除では、「単語グループ名」に所属グループ、「名称」に対象項目を独立表示する
- PCでは「キャンセル」と「削除」を右下へ隣接し、モバイルではヘッダー左のキャンセルと右の削除へ切り替える
- 認可・存在・所属を確認し、配下単語を削除してから最後にグループを削除する。途中失敗はエラーとして返し、画面を再取得して残ったグループから再試行する。専用の削除記録は保存しない。詳細は[単語グループ削除の復旧](../../backend/quicktext-deletion.md)を参照する
- 項目は指定IDだけで物理削除する
- 削除成功後、グループは画面内から除去し、項目は対象グループの一覧を再取得する
- 削除成功時、またはグループ削除失敗後の再取得で対象が存在しない場合に確認ダイアログを閉じる。操作起点が残る場合は元の操作へ、削除で消えた場合は同種の次の操作、前の操作、一覧見出しの順でフォーカスを戻す。失敗後も対象が残っていれば確認ダイアログを維持して再操作できる状態へ戻す

### 並び替え

- グループまたはグループ内項目をドラッグすると、画面上の配列順で1から再採番する
- 並び替えはドラッグ操作だけを使用し、先頭・上・下・最後へ移動する専用ボタンは表示しない
- ドラッグハンドルはクリック動作やキーボード操作を持つボタンとして扱わず、ポインティングデバイス用の非操作要素として表示する
- グループは全グループ、項目は対象グループの全項目について、個別PATCHを`Promise.all`で並行実行する
- 成功時は再取得せず、画面内の再採番結果を維持して成功スナックバーを表示する
- 認証エラーの401ではログアウトしてログイン画面へ遷移し、グループ全件または対象グループの項目を再取得する
- 並び替えの永続化中は`sending=true`とし、ドラッグ、作成、編集、削除を無効化して別操作を開始しない
- 認証エラー以外の失敗では移動前の配列と`order`へ戻す。認証エラーでは`sending`を解除した後に対象一覧を再取得する

### 行操作とアクセシブルな名前

- グループ内の「単語作成」はグループ自身の行操作と別の操作群として表示する
- グループと項目の行操作は「削除」「編集」の順で常に横並びにする
- 反復するグループの編集・削除ボタンは対象グループ名をアクセシブルな名前に含める
- 反復する項目の編集・削除ボタンは所属グループ名と対象項目名をアクセシブルな名前に含める
- 「単語作成」ボタンも追加先グループ名をアクセシブルな名前に含める

### フロア／ルームへの初期コピー

- フロア作成時、その時点の共通の単語全グループと項目をフロア単語へコピーする
- グループIDはフロア用IDへ付け替え、フロア作成者をグループ所有者として保存する
- 原文、原文言語、表示順番を引き継ぎ、作成するフロアの`target_langs`に従ってフロア用翻訳配列を新たに作成する
- 共通の単語の後続作成・編集・削除・並び替えは既存フロアへ伝播しない
- ルーム作成時は共通の単語ではなく、その時点の対象フロア単語をルームへコピーする

## 入力条件

- グループタイトル: 必須、前後の空白除去後1〜200文字
- 項目ラベル: 必須、前後の空白除去後1〜200文字
- `order`は1〜100。現在の最大値に1を加えて採番するため、最大値が100の場合は新規作成できない
- 同一`order`を禁止するDB制約はなく、同時作成や個別PATCHの途中失敗で重複する場合がある
- `lang`は対応するISO 639-1言語コードが必須である
- ダイアログに言語選択欄はない。新規作成では現在の表示言語を使用する
- 編集では保存済みの`lang`を維持し、未設定または非対応の場合だけ現在の表示言語を使用する。現在の表示言語も利用できなければ`ja`とする
- 共通の単語自身は翻訳を作成・保存しない

## 通信・エラー時の動作

### 使用するAPI

| 用途 | Method / Path | 画面での利用 |
| --- | --- | --- |
| グループ全件取得 | `GET /api/management/quick-text/groups/all` | 初期表示・グループ保存後に使用 |
| グループページング | `GET /api/management/quick-text/groups?page=:page` | 未使用 |
| グループ作成 | `POST /api/management/quick-text/groups` | 使用 |
| グループ更新 | `PATCH /api/management/quick-text/groups/:id` | 編集・並び替えで使用 |
| グループ削除 | `DELETE /api/management/quick-text/groups/:id` | 使用 |
| 項目一覧 | `GET /api/management/quick-text/groups/:groupId/items` | 使用 |
| 項目作成 | `POST /api/management/quick-text/groups/:groupId/items` | 使用 |
| 項目更新 | `PATCH /api/management/quick-text/items/:id` | 編集・並び替えで使用 |
| 項目削除 | `DELETE /api/management/quick-text/items/:id` | 使用 |

- 全APIにBearer JWTとAdministrator権限が必要である
- 項目一覧は指定グループの存在を確認せず、そのIDに一致する項目を返す。グループが存在しなければ通常は空配列となる
- 項目作成だけは対象グループの存在を確認する
- 認証エラーの401はエラー表示後にログアウトしてログイン画面へ遷移する
- 403、404、入力不正、通信失敗はエラーを表示して現在画面またはダイアログを維持する

### 読み込み中・データなし・エラー時

- グループ全件取得、削除、並び替えの永続化中は画面の`sending`をtrueにし、ドラッグ、作成、編集、削除開始を無効化する
- 各保存ダイアログは独立した送信状態で多重送信を抑止する
- グループが0件の場合は専用の空状態を表示する。グループ取得エラーでは再試行ボタンを表示する
- グループに項目がない場合は「単語がありません」と表示する
- 項目の並行取得ではグループごとに読込中、空、失敗を表示し、成功したグループの項目は維持する。失敗したグループには再試行ボタンを表示する
- API失敗は処理別文言とAPIエラー詳細をalertスナックバーへ表示する
- グループ削除失敗後は一覧と配下単語を再取得し、完了まで操作を抑止する。グループが残っていれば確認ダイアログを維持して再試行できる。再取得で存在しなければ確認を閉じる
