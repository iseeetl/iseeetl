# AI解析設定管理（/management/ai-analysis-settings）

## 概要

Administratorが共通AI解析設定を検索・作成・更新・物理削除する管理画面です。管理メニューの「AI解析設定管理」から開きます。フロア／ルーム設定はこのルートではなく、[ルーム画面](Room.md)の各設定ダイアログを使用します。データと権限の基準は[AI解析設定・実行仕様](../../ai-analysis.md)、API フィールドは[AI解析設定API](../../backend/api/ai-analysis-settings.md)を参照してください。

## 利用条件・開き方

### URL

- パス: `/management/ai-analysis-settings`
- ルート名: `AIAnalysisSettingManagement`
- コンポーネント: `frontend/src/views/management/AIAnalysisSettingManagement.vue`
- メタ情報: `isManagement: true`

### 利用条件

- Administratorだけが利用できます。管理ルートガードに加え、バックエンドAPIが毎回認証・認可します。

OpenAI機能の有効状態は画面・タグ選択・管理操作の表示条件ではありません。提供元が無効でも設定を管理できます。設定0件は正常な空状態として表示します。

## 画面構成

共通・フロア・ルーム設定の一覧表は、列見出しの背景をタグ一覧と同じ薄い灰色にします。

### 共通設定一覧

- タグ、解析種別、追加指示、「付加情報を行うユーザ」、操作の5列を表示します。更新番号と削除状態は表示しません。一覧表には画面固有の名前を付けます。
- タイトル行の右端に短い「作成」ボタンを置きます。検索欄と検索ボタンを表示します。検索ボタンは主要操作として塗りつぶし表示します。
- 検索は100文字以下で、タグ名・翻訳名、解析種別、「付加情報を行うユーザ」のユーザ名が対象です。
- 初回読込、再読込、空状態、検索0件、通信エラーは管理一覧の共通表示を使います。
- 行全体は操作対象にしません。各行は「削除」「編集」の順に操作を表示します。
- 共通設定一覧表は列ごとの幅と最小幅を持ち、列見出しを文字単位で分断しません。「編集」と「削除」は
  同じ行に並べ、利用可能幅が不足する場合は列名付きカードへ切り替えます。
- タグまたは結果ユーザの参照先が欠損した保存済み設定も一覧へ残し、欠損フィールドは「参照先なし」と表示します。参照先が論理削除済みの場合は返却された公開名を表示しつつ、欠損時と同じ利用不可状態として扱います。いずれも編集を無効化し、理由を編集ボタンへ関連付けて表示します。削除は利用できます。管理画面に欠損・削除済み参照の修復導線はありません。

## 操作と動作

### 削除

- 削除は、解析種別と対象タグを示す確認ダイアログから実行します。「この操作は元に戻せません」と案内し、確定するとレコードを物理削除します。コピー済みのフロア・ルーム設定は維持します。
- 更新・削除では内部で保持した`revision`を送り、他の利用者の変更と競合していないことを確認します。
- 送信中と成功後の一覧再取得中は対象とダイアログを維持し、閉じる操作と二重送信を抑止します。通常の失敗は対象を維持して再操作できます。
- リビジョンの競合（409）や対象の削除（404）では自動再送せず編集・確認ダイアログを閉じ、最新一覧を取得してエラーを通知します。利用者は最新の行を選び直します。

### 作成・編集ダイアログ

1. 共通タグを選ぶ。
2. `vision`、`audioScene`、`speech`、`video`、`conversation`から解析種別を選ぶ。
3. 追加指示を入力する。最大2000文字、容量は8000バイト以内。音声文字起こし（`speech`）は224バイト以内。文字数・容量の数え方は[AI解析仕様](../../ai-analysis.md#文字数容量の数え方)を参照する。
4. 「付加情報を行うユーザ」の選択を確認する。空欄または変更する場合は、ユーザ名を100文字以内で入力して検索し、有効なユーザを選ぶ。メールは表示しない。
5. 作成時は「作成」、編集時は「保存」を選ぶ。

追加指示欄には「最大2000文字」と表示します。音声文字起こしでは、日本語で約74文字が目安で、文字種により入力できる文字数が異なることを案内します。あわせて、外部APIの制約を考慮し、224バイト以内に制限していることを表示します。「付加情報を行うユーザ」はユーザ名の入力欄と「検索」ボタンを同じ行に表示します。

共通・フロア・ルーム設定の新規作成時は、対象範囲の初期ユーザAPIを呼び出し、有効な`SUPPORT_USER_ID`のユーザを選択中として表示します。未設定・無効なIDの場合は空欄です。初期選択から別のユーザへ変更でき、編集時は保存済みユーザを維持します。

初期ユーザの取得中はユーザ検索・選択と保存を無効にしますが、他の項目への入力とキャンセル・戻る操作は利用できます。初期選択だけでは未保存の変更とせず、取得中に利用者が入力した変更は維持します。閉じた画面や変更前の対象へ届いた応答は反映しません。取得失敗は通知し、空欄のまま手動で検索・選択できます。

検索前は候補領域、「検索結果」の表題、0件案内を表示しません。検索に成功した後だけ「検索結果」と縦並びのラジオボタン候補を表示し、0件の場合は「該当するユーザが見つかりません」と表示します。編集時は保存済みユーザを検索前にも選択中として表示し、検索後の候補にも選択状態を維持します。

共通・フロア・ルーム設定の作成・編集では、選択中のユーザ名の直前に28pxの円形プロフィール画像を表示します。検索候補はラジオボタン、画像、ユーザ名の順に8px間隔で並べます。画像未設定・取得失敗時は既存の人物アイコンを表示し、長いユーザ名は画像の大きさを保って折り返します。画像は装飾として扱い、ユーザ名の読み上げを重複させません。

共通設定の入力ダイアログは、次の構成にします。

- 配置: フロア／ルーム設定の入力画面と同じ920px幅で、縦一列のフォームと検索結果のラジオボタン一覧を表示します。編集時は見出し直後に「対象設定」と変更前のタグ・解析種別を独立表示し、入力中も元の対象を判別できるようにします。
- 操作ボタン: 広い画面では下部右側に、作成時は「キャンセル」と「作成」、編集時は「キャンセル」と「保存」を隣接して配置します。狭い画面では左上に閉じるアイコン、右上にチェックアイコンを同じ高さで表示します。
- 項目名: タグ、解析種別、「付加情報を行うユーザ」の項目名は、未選択時も操作部品の上部に表示し、選択肢の案内と重ならないようにします。
- 入力状態: 選択操作中に再描画が発生しても選択値を維持します。入力検証と保存には画面上で選んだ値を使用します。

作成・編集の開始時から入力値を変更してキャンセル、Escape、外側クリックを行うと「変更内容を破棄しますか？」の確認を表示します。変更していない場合と開始状態へ戻した場合は確認せず閉じます。保存中は重複送信とダイアログ終了を抑止します。作成・更新成功時は一覧を再取得します。

### フロア／ルーム設定ダイアログ

ルーム画面では、Administratorと対象フロアを作成したEditorに次を表示します。

- フロアタグ操作の隣にフロアAI解析設定ボタン
- 各ルームタグ操作の隣にルームAI解析設定ボタン

ダイアログの初期画面は有効な設定の一覧だけを表示します。件数を左、作成操作を一覧上部右、閉じる操作をPCの下部右に配置します。「作成」または各設定の「編集」を選ぶと、別の作成・編集ダイアログを重ねず、同じダイアログ内の入力画面へ切り替えます。入力画面ではタイトルを「AI解析設定を作成」または「AI解析設定を編集」に切り替え、作成時は「戻る／作成」、編集時は「戻る／保存」を表示します。表示していない画面は操作と読み上げの対象にしません。

フロア設定は「対象フロア」、ルーム設定は「対象ルーム」に、ルーム一覧画面と同じ翻訳済み表示名を示します。対象名は一覧、作成・編集、削除確認で維持します。

一覧は広い画面ではタグ、解析種別、追加指示、「付加情報を行うユーザ」、操作の5列一覧表、狭い画面では設定ごとのカードに切り替えます。全行が有効なため状態列・状態バッジは表示しません。カードはタグを見出しにし、解析種別、「付加情報を行うユーザ」、追加指示、編集・削除操作を項目ごとに表示します。`revision`は画面へ表示しませんが、更新・削除リクエストの競合制御には保持して使用します。

タグと解析種別の項目名は未選択時も操作部品上部に表示し、選択肢の案内と分離します。Administratorと対象フロアを作成したEditorは、フロア／ルームごとの認可を伴う検索APIで有効な「付加情報を行うユーザ」を検索・選択し、作成・更新リクエストへ`result_user`を含めます。親設定プレビューは表示せず、親タグ・親設定がない組合せも保存できます。フロア／ルーム作成時に自動コピーされた設定の来歴は維持しますが、以後の作成・更新・削除と`result_user`は親設定から独立しています。

フロア／ルーム設定の入力条件、ユーザ検索、検索前後の候補表示は共通設定と同じです。

一覧取得では読込中、正常一覧、取得成功後の0件、取得失敗を区別します。取得失敗時はインラインの再試行を表示します。GET中も一覧ダイアログを閉じることができ、終了後または対象変更後に完了した古い応答は表示へ反映しません。設定の送信・一覧反映処理中は終了と追加操作を抑止します。

「付加情報を行うユーザ」の検索は変更送信用の`sending`とは別の`searching`で管理します。検索中は検索入力欄、検索ボタン、表示済みラジオボタン候補を無効にし、重複検索と設定保存を抑止して進捗を表示します。一方、戻る、Escape、背景クリックは抑止しません。入力画面またはダイアログを閉じた後、適用範囲・フロアID・ルームIDを変更した後に完了した検索応答はリクエスト世代で破棄します。

入力画面は開始時との差分がある場合だけ、戻る、Escape、背景クリックで「変更内容を破棄しますか？」の確認を表示します。変更がない場合は即座に一覧へ戻ります。入力エラー時は最初のエラー項目へフォーカスします。

削除確認はフロア／ルームのどちらも「対象設定」に解析種別とタグを表示し、フロア設定は「対象フロア」、ルーム設定は「対象ルーム」も表示します。フロア／ルーム設定は元に戻せないことを確認して物理削除し、一覧から消え、画面とAPIに復元操作を提供しません。同じタグ・解析種別が再び必要な場合は新しい設定として作成します。削除確認中も親一覧を背後に維持し、通常の削除失敗では確認対象を維持して再試行できます。更新・削除の409と対象消失の404では自動再送せず、最新一覧を読み直して通知します。

入力画面を保存せずに戻った場合は開始元へ、保存した場合は再取得した一覧の作成・更新対象へフォーカスを移し、対象が一覧にない場合はダイアログのタイトルへ戻します。削除成功後は次の設定、前の設定、一覧見出しの順でフォーカスを移します。削除を取り消した場合は開始した削除操作へ戻します。ダイアログ自体を終了した場合は、可能な場合に画面側の開始元へフォーカスを戻します。

### AI結果のタイムライン表示

AI結果は通常の付加情報と同じコンポーネントで表示・編集します。保存済みの音声文字起こし結果が400文字を超えていても、そのまま表示します。編集して保存する場合は400文字以内に短縮します。絵文字などは、1文字を2文字以上として数える場合があります。

### アクセシビリティとモバイル

- 一覧の列見出し、各操作ボタン、ダイアログのタイトル、フォーム操作部品にプログラムによるラベルを付けます。
- ルーム設定の対象ルーム名と、フロア／ルーム設定の削除対象はダイアログの説明へ関連付け、利用者が入力した文字列は`dir="auto"`で表示します。
- 一覧画面と入力画面でダイアログのタイトルを切り替え、戻るボタンにもアクセシブルな名前を付けます。内部画面の切替後は、表示した入力操作部品または一覧上の適切な復帰先へフォーカスを移します。
- フロア／ルーム設定の内部入力画面では、一覧へ戻る左向きの山形アイコンと作成・保存用チェックアイコンを表示します。
- 読込中と0件はstatus、取得失敗・競合はalertとして通知し、取得失敗には再試行操作を付けます。
- 共通設定の入力ダイアログでは、Escape・背景クリック・キャンセルボタンでダイアログを終了します。フロア／ルーム設定では、一覧画面のEscape・背景クリック・閉じるボタンはダイアログを終了し、内部入力画面のEscape・背景クリック・戻るボタンは設定一覧へ戻ります。設定変更の送信・一覧反映処理中はいずれも受け付けませんが、結果ユーザ検索中はフロア／ルーム設定の内部入力画面から戻る操作を利用できます。
- 共通設定一覧は横スクロールさせず、1100px以下で一覧表をカードへ切り替えます。フロア／ルーム設定ダイアログは896px以下で一覧表をカードへ切り替え、列見出しが縦に分断されないようにします。
- 狭い画面ではダイアログフォームと操作ボタンを利用可能な横幅に合わせて折り返します。
- 利用者が入力したタグ名、追加指示、ユーザ名は`dir="auto"`で表示します。

## 通信・エラー時の動作

### 使用するAPI

| 目的 | Method / Path | 主な送信値 | 画面での扱い |
| --- | --- | --- | --- |
| ページング一覧 | `GET /api/aianalysissetting/management/paginate` | クエリ: `page`, `search` | バックエンドの集計パイプラインによるページングが検索・並び替え・件数を適用 |
| 作成 | `POST /api/aianalysissetting/management/create` | タグ、解析種別、prompt、結果ユーザ | 成功後に現在一覧を再取得 |
| 更新 | `POST /api/aianalysissetting/management/update` | タグ、解析種別、prompt、結果ユーザ、`_id`、`revision` | リビジョンの一致を確認し、成功後に現在一覧を再取得 |
| 削除 | `POST /api/aianalysissetting/management/delete` | `_id`、`revision` | 物理削除後に現在一覧を再取得 |

一覧は1ページ10件です。`revision`は画面には表示せず、更新・削除の競合防止用に保持します。
