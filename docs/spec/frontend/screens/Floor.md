# フロア（/、/page/:ページ）

## 概要

- 閲覧可能なフロアを検索・ページングして表示し、選択したフロアのルーム一覧へ進む
- 管理権限がある場合は、フロアの作成・編集・削除と表示状態の一括変更を行う

## 利用条件・開き方

- アプリメニューの「フロア一覧」、ログイン後の通常遷移先、またはURLへの直接アクセス

### URL

| パス | ルート名 | 用途 |
| --- | --- | --- |
| `/` | `Floor` | 1ページ目を表示する |
| `/page/:page` | `FloorPage` | 指定ページを表示する |

- コンポーネントはいずれも`frontend/src/views/Floor.vue`である
- メタ情報はいずれも`isPublic: true`, `title: 'フロア一覧'`であり、ゲストも利用できる
- `:page`を省略した場合は1ページ目とする
- `:page`は1以上の10進整数だけを有効とする。`0`、負数、小数、文字列、安全な整数を超える値は、クエリを保持して`/page/1`へ置換する

### 利用条件

#### 一覧に含まれるフロア

| 利用者 | 公開フロア | 非表示フロア |
| --- | --- | --- |
| ゲスト | 表示 | 表示しない |
| Administrator | 表示 | 表示 |
| Editor | 表示 | 自分が作成したフロア、またはフロアメンバーであるフロアを表示 |
| Author／developer | 表示 | フロアメンバーであるフロアだけ表示 |

- 論理削除されたフロアは全利用者の一覧から除外する
- `floor_display_hidden`は一覧への表示条件であり、フロア配下への直接URLアクセスを禁止する認可条件ではない
- フロアメンバーであっても、この画面でフロア自体を編集・削除する権限は得ない

#### 管理操作

| 操作 | Administrator | フロア作成者であるEditor | その他のEditor | フロアメンバー／その他 |
| --- | --- | --- | --- | --- |
| フロア作成 | 可 | 可 | 可 | 不可 |
| 対象フロアの編集・削除 | 可 | 可 | 不可 | 不可 |
| 表示状態の一括変更 | 全アクティブフロア | 自分が作成したアクティブフロア | 自分が作成したアクティブフロア | 不可 |

- 作成・一括変更ボタンはVuexに保持するシステムロールが`Administrator`または`Editor`の場合だけ表示する
- 各カードの編集・削除ボタンは、Administrator、またはカードの`user._id`がログインユーザIDと一致するEditorだけに表示する
- Editor向け画面にも「全フロア非表示」「全フロア表示」と表示するが、バックエンドで変更する範囲はそのEditorが作成したフロアだけである

## 画面構成

- 翻訳対象のH1「フロア一覧」
- フロア作成、全フロア非表示、全フロア表示の管理ボタン
- 検索入力と検索ボタン
- フロアカード一覧
  - フロア画像。画像がない場合は`/assets/image/floor_default.jpg`
  - 非表示中チップ
  - 表示言語に対応するタイトル・説明
  - 作成者のアイコン・名前、作成日
  - 権限がある場合の編集・削除ボタン
- 最初・前・最大5ページ分の番号・次・最後からなるページャ
- `EditFloorDialog`、`DeleteFloorDialog`、`UpdateFloorDisplayConfirm`

## 操作と動作

### 初期表示・一覧取得

- ルートの`:page`と`q`から表示条件を復元し、ゲストは`POST /api/floor/guest/paginate`、ログイン中は`POST /api/floor/paginate`を呼ぶ
- 1ページは9件で、`created_at`の降順に表示する
- レスポンスの`docs`、`page`、`pages`、`total`を一覧・現在ページ・最終ページ・総件数へ反映する
- 連続して一覧取得した場合、リクエスト番号が古いレスポンスは画面状態へ反映しない
- ページャは`router-link`ではなく通常の`a`要素で画面を再読込し、遷移後にリンクへフォーカスが残らないようにする。検索クエリはページリンクへ引き継ぐ
- ルームまたはタイムラインからVuexへ引き継がれた`errorMessage`があれば、初期表示時にalertのスナックバーで表示してから消去する

### 検索

- 検索時に入力を検証し、1〜100文字の範囲外なら検索しない。空欄は検索条件の解除として受け付ける
- 検索入力は画面上で最大100文字とし、検索語を`q` クエリへ保存する
- 検索ボタンを押すと1ページ目へ移動し、ルート変更を契機に一覧を再取得する
- 空文字で検索した場合は、検索を解除してクエリなしの`/page/1`へ移動する
- 空文字でない場合は既存クエリを保持し、`q`だけを入力値で更新する
- バックエンドは元の`title`と`description`を部分一致検索する。翻訳配列のタイトル・説明は検索対象に含めない
- カードのタイトル・説明は[翻訳済みデータの表示](../style-and-i18n.md#翻訳済みデータの表示)に従い、原文と表示言語が異なる場合だけ対象言語の翻訳を使う。翻訳がなければ原文を表示する

### フロア作成・編集

#### 入力項目

- タイトル: 必須、100文字以下
- 説明: 200文字以下
- 原文言語と翻訳対象言語。新規作成時の原文言語は現在の表示言語、編集時は既存フロアの原文言語を維持する。翻訳対象言語の選択UIはGoogle Translateが利用可能な場合だけ表示する
- フロア画像: PNG／JPEG
- フロアを非表示にする設定

- Google Translateが無効な場合、新規フロアの`target_langs`は空配列とする。既存フロアの編集では保存済み`target_langs`を画面に表示せず保持し、機能OFFだけを理由に消去しない

#### ダイアログ操作

- 新規作成は「フロアを作成」と「キャンセル／作成」、編集は「フロアを編集」と「キャンセル／保存」を使用する。編集時だけ、フォームとは独立した「対象フロア」にフロアカードと同じ翻訳済み表示名を示す
- フォームは「基本情報」「画像」「表示・通知」に区分する。PCは共通幅480px、スマートフォンは1列とし、スマートフォンでは左上のキャンセルと右上の作成・保存を使用する
- 入力値、翻訳対象言語、画像の状態を変更してからキャンセル、Escape、背景クリックを行うと破棄確認を表示する。開始時と同じ状態へ戻した場合、または変更がない場合は確認せず閉じる
- 入力エラーが複数ある場合は、最初のエラー項目へスクロールしてフォーカスする。画像変換中に終了を求めた場合は破棄確認を表示し、破棄時は変換結果を無効化して閉じる。保存中は終了と重複送信を抑止する

#### 画像処理

- フロントエンドは選択画像を最大幅800pxに縮小し、品質0.8のJPEG Blobへ変換する
- フロントエンドの3MB上限は変換後Blobに対して確認する
- バックエンドは申告MIMEだけでなくPNG／JPEG署名、実形式、デコード可否、縦横、展開後40,000,000画素以下を検査し、メタデータを引き継がず再エンコードする
- 画像なしの作成はフロア作成APIだけを呼ぶ。画像ありの作成はフロア作成、画像アップロード、返された画像名によるフロア更新の順に呼ぶ
- 画像を変更する編集は、画像アップロード後にフロア更新を行う。DB更新後に以前の画像を削除する
- 保存済み画像と選択中画像の分離、取消・削除、同じファイルの再選択、保存失敗時の状態は[保存済み画像の差し替えと取消](../media-input.md#保存済み画像の差し替えと取消)に従う

#### 保存後の処理

- 作成時にフロアと翻訳を保存し、管理用の共通タグをフロアタグへ、共通の単語のグループ・項目をフロア単語へコピーする
- フロア用メディアディレクトリを作成する
- Google Translateが有効な場合、翻訳対象言語の変更に合わせてフロアと配下データを再翻訳する。対象は[フロア管理の翻訳と下位データへの影響](FloorManagement.md#翻訳と下位データへの影響)を参照する
- 作成・編集・削除・一括変更はSocket.IOのフロア更新イベントを送信しない

### 削除・表示状態の一括変更

- 「フロアを削除」確認では「対象フロア」にフロアカードと同じ翻訳済み表示名を示し、通常操作では対象フロア、配下ルーム、タイムラインを利用できなくなることを説明する。初期フォーカスは「キャンセル」とし、確定操作だけを危険操作として表示する
- 削除は確認ダイアログを経てフロアを論理削除する
- 削除成功後は対象フロア配下の全Socketへ`ACCESS_REVOKED`（`floor_deleted`）を通知して切断する。対象タイムラインはログイン状態を維持してフロア一覧へ遷移する
- フロア削除は配下のルーム、フロアタグ、フロア単語、フロア／ルームAI解析設定、メディアを連鎖削除しない。有効なAI解析設定が存在しても削除できるが、通常の一覧・詳細APIと解析実行では削除済みフロアを起点に利用できなくなる。フロア復元後は有効な設定を既存状態のまま再び利用できる
- 一括変更は`floor_display_hidden`を、Administratorは全アクティブフロア、Editorは自分が作成したアクティブフロアへ設定する
- 作成・編集・削除・一括変更の成功後は、検索条件を保持して1ページ目へ戻し、一覧を再取得する
- すでに1ページ目の場合は同じURLへの遷移に依存せず、一覧取得を直接実行する
- ダイアログを閉じた後は、ダイアログを開いたボタンへフォーカスを戻す。削除成功後は次のフロア、前のフロア、作成ボタン、一覧見出しの順でフォーカス先を選ぶ

## 通信・エラー時の動作

- 作成・画像アップロード・画像名更新は別APIであり、途中失敗時に作成済みフロアまたは未参照画像が残る
- DB更新後の旧画像削除に失敗しても更新は成功し、ファイルが残る場合がある

### 使用するAPI

| 用途 | Method / Path | 認証・主な条件 |
| --- | --- | --- |
| ゲスト一覧 | `POST /api/floor/guest/paginate` | JWT不要、公開フロアだけ |
| ログイン一覧 | `POST /api/floor/paginate` | JWT必須、ロールとフロアメンバー所属で非表示フロアを追加 |
| 作成 | `POST /api/floor/create` | Administrator／Editor |
| 更新 | `POST /api/floor/update` | Administrator／作成者Editor |
| 削除 | `POST /api/floor/delete` | Administrator／作成者Editor |
| 表示状態の一括変更 | `POST /api/floor/update/floordisplayhidden` | Administrator／Editor |
| 画像アップロード | `POST /api/fileupload/floor/image` | 対象フロアを管理できる利用者 |

### 読み込み中・データなし・エラー時

- 一覧取得中は検索入力を無効化する。管理ダイアログは各コンポーネント内で多重送信を抑止する
- 一覧が0件の場合はカードを表示しない。専用の空状態メッセージや再読込ボタンはない
- API失敗は処理別の文言とAPIエラー詳細をalertのスナックバーへ表示する
- 認証エラーの401はログアウト処理を行いログイン画面へ遷移する
- 作成・編集・削除・一括変更に失敗した場合はダイアログまたは現在の一覧を維持し、再操作できる
