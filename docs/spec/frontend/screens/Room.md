# ルーム（/floor/:floor_id）

## 概要

- 指定フロアの閲覧可能なルームを表示し、入室判定後にタイムラインへ進む
- 権限がある場合は、ルーム、表示順、公開状態、タグ、単語、フロアメンバー、ルームメンバー、キック済みユーザを管理する

## 利用条件・開き方

- フロアのフロアカード、または`/floor/:floor_id`への直接アクセス

### URL

- パス: `/floor/:floor_id`
- ルート名: `Room`
- コンポーネント: `frontend/src/views/Room.vue`
- メタ情報: `isPublic: true`, `title: 'ルーム一覧'`
- ルート自体はゲストへ公開する。画面内ではログイン状態、システムロール、フロアメンバー／ルームメンバー所属、キック状態、ルーム設定を別々に判定する

### 利用条件

#### ルーム一覧に含まれる範囲

| 利用者 | 公開ルーム | 非表示ルーム | メンバー限定ルーム |
| --- | --- | --- | --- |
| ゲスト | 表示 | 表示しない | 一覧には表示するが入室不可 |
| Administrator | 表示 | 表示 | 表示・入室可 |
| FloorEditor | 表示 | 表示 | 表示・入室可 |
| フロアメンバー | 表示 | 表示 | 表示・入室可 |
| ルームメンバー | 表示 | 表示しない | 対象ルームは一覧表示・入室可。ただし非表示なら一覧に含めない |
| Author／developer | 表示 | 表示しない | 一覧には表示するが入室不可 |

- 論理削除されたルームは一覧から除外する
- ログイン一覧で非表示ルームを取得できるのはAdministrator、FloorEditor、フロアメンバーである。ルームメンバー所属だけでは非表示ルームの一覧権限を得ない
- `member_only`は入室認可、`room_display_hidden`は一覧表示の制御である。IDを知っている利用者の直接入室を`room_display_hidden`だけで拒否しない
- `floor_display_hidden`もこの画面への直接アクセス認可には使わない。アクティブなフロアであれば、その配下の閲覧可能なルームを取得できる
- ログインユーザがKickedUserに登録されている場合は、システムロールや所属より優先してフロアと配下ルームへのアクセスを拒否する

| 全ルーム表示・非表示 | 可 | 可 | 可 | 不可 | 不可 |
| ルーム並び替え | 可 | 可 | 可 | 不可 | 不可 |

| フロアメンバー招待 | 可 | 可 | 不可 | 不可 | 不可 |
| フロアメンバー一覧 | 可 | 可 | 可 | 不可 | 不可 |
| フロアメンバー削除 | 可 | 可 | 不可 | 不可 | 不可 |

- ルームメンバー招待と一覧のボタンは`member_only=true`のルームカードだけに表示し、ルーム単語操作の直後へ配置する
- 招待ボタンはAdministrator、FloorEditor、フロアメンバーに表示する。一覧ボタンはこれらに加え、`current_user_is_room_member=true`の対象ルームメンバーにも表示する
- ルームメンバー本人の脱退操作はこの画面へ移動せず、対象ルームのタイムラインのヘッダーに配置する

## 画面構成

- フロア一覧へ戻る`BackButton`
- フロア画像を使う背景、翻訳後のフロアタイトルを含むH1、フロア説明
- 権限に応じたルーム・タグ・AI解析設定・単語・フロアメンバー・キック済みユーザの管理ボタン
- ドラッグ可能なルーム一覧
  - ルーム画像、タイトル、説明
  - 作成者のアイコン・名前、作成日、アクティブな最新投稿の日時
  - `非表示中`、`メンバー限定`、`ゲストはリアクションのみ`、`外部SNS連携`の状態チップ
  - 権限がある場合の並び替えハンドル、削除、ルームタグ、ルームAI解析設定、ルーム単語、ルームメンバー招待・一覧、編集ボタン
- ルーム、タグ、AI解析設定、単語、フロアメンバー、ルームメンバー、キック済みユーザ、公開状態の各ダイアログ

- `notification`設定はルーム編集項目として保持するが、一覧カードには状態チップを表示しない
- 既存ルームを操作するダイアログは、タイトル直下の「対象ルーム」にルームカードと同じ翻訳済み表示名を示す。編集フォームでタイトルを変更しても、保存完了までは開始時の対象名を維持する。新規作成には「対象ルーム」を表示しない
- フロア／ルームメンバーの招待と一覧では「できること」「できないこと」を見出し付きの箇条書きで示す。フロアメンバーが自分で作成したルームのメンバーを削除できること、および上位権限が優先することを注記する。
- フロア／ルームAI解析設定の編集・削除ボタンは、作成ボタンと同じ通常の密度に揃える。
- ダイアログを閉じた後は原則として開いたボタンへフォーカスを戻す。入れ子のタグ・AI解析設定・単語・メンバー削除確認では親一覧を維持し、取消後または成功後に一覧内の操作へフォーカスを戻す

## 操作と動作

### 初期表示

1. ログイン中の場合は`POST /api/floor/role`で対象フロアにおける最新ロールを取得する
2. ログイン中の場合は`POST /api/kickeduser/check`を実行する。キック済みなら一覧を取得せずフロアへ戻す
3. `POST /api/floor/detail`でアクティブなフロアのタイトル、説明、原文言語、翻訳、画像を取得する
4. フロアIDと表示用タイトルをVuexへ保存する
5. ゲストは`POST /api/room/guest`、ログイン中は`POST /api/room`でルーム一覧を取得する

- フロア・ルームのタイトルと説明は[翻訳済みデータの表示](../style-and-i18n.md#翻訳済みデータの表示)に従う。原文と表示言語が同じなら原文を使い、異なる場合は対象言語の翻訳、なければ原文を表示する
- 表示中に言語が変わった場合は、取得済みのフロア詳細からタイトルと説明を再計算し、H1、Vuex、フロア関連ダイアログの対象名へ反映する
- ログイン向け一覧の各ルームには、現在のログインユーザがそのルームのルームメンバーであるかを示す`current_user_is_room_member`が含まれる。この値はメンバー限定ルームの「ルームメンバー一覧」ボタンをカードへ表示する判定に使用する
- ゲスト向け一覧には`current_user_is_room_member`を含めない
- フロアから戻った際にVuexの`tempRoomId`がある場合は、一覧描画後に対象ルームリンクへフォーカスを戻して値を消去する
- 初期化のいずれかが失敗した場合は、エラーをVuexへ保存してフロアへ戻す。認証エラーの401の場合はあわせてログアウトしログイン画面へ遷移する

### Google Analyticsによる利用状況計測

Google Analyticsが利用可能な場合、ルーム一覧のAPI初期化に成功したアクセスだけをリソース付き
`page_view`として送る。全体契約は[ルーティング](../routing.md#google-analyticsのページ計測)と
[Cookie・ブラウザ保存・外部送信](../cookies-and-external-transmissions.md#送信イベントとパラメータ)を参照する。

- 画面初期化時にルートのフロアIDから世代付きトークンを取得し、現在の利用者に必要なロール・キック検査、フロア詳細、ルーム一覧取得の成功後に計測を開始する
- ルートフロアIDと取得した`Floor._id`が一致する場合だけ、`page_group=room_list`のコンテキストを有効にする。名称には検証済みの原文の`Floor.title`を使い、翻訳後の表示タイトル、フロア説明、ルーム一覧の名称は使用しない
- 初期化失敗、キック、ルート不一致、離脱、画面破棄、古いAPI応答では計測を開始しない。遷移中のコンテキスト維持、送信順序、重複抑止は前述の全体契約に従う
- Analyticsの失敗はルーム画面の取得、表示、遷移、スナックバーへ影響させない

### ルーム入室

- ルームカードを選択するたび、ログイン中であれば`POST /api/chat/role`から最新の対象ルームロールを取得する
- `member_only=false`なら、ゲストとログインユーザの双方が`/floor/:floor_id/room/:room_id`へ進める。ただしキック・認証・アクティブ状態のバックエンド検査は別途適用する
- `member_only=true`なら、Administrator、FloorEditor、フロアメンバー、対象ルームメンバーだけが入室できる
- ゲスト、および対象所属を持たないAuthor／developerはメンバー限定ルームへ入室できない
- 権限不足はalertのスナックバーで通知して現在画面を維持する。認証エラーの401はログアウトしログイン画面へ遷移する
- 画面初期化時のフロアロールだけを使い回さず、カード選択時の最新レスポンスで入室可否を判定する

### ルーム作成・編集

#### 入力項目

- タイトル: 必須、100文字以下
- 説明: 200文字以下
- ルーム画像: PNG／JPEG
- ゲストはリアクションのみ
- 招待メンバーのみ
- 通知表示。新規作成時の既定値は有効
- 外部SNS連携ボタン
- ルームを非表示にする設定

- 新規作成時の原文言語は現在の表示言語とし、翻訳対象には所属フロアの対象言語を使用する
- 編集時は既存ルームの原文言語を維持する

#### ダイアログ操作

- 新規作成は「ルームを作成」と「キャンセル／作成」、編集は「ルームを編集」と「キャンセル／保存」を使用する。編集時だけ、フォームとは独立した「対象ルーム」に開始時の翻訳済み表示名を示す
- 通常のルームフォームは「基本情報」「画像」「参加・投稿設定」「表示・通知」の4区分で表示する。PCは共通幅480px、スマートフォンは1列とし、スマートフォンでは左上のキャンセルと右上の作成・保存を使用する
- 入力値または画像の状態を変更してからキャンセル、Escape、背景クリックを行うと破棄確認を表示する。開始時と同じ状態へ戻した場合、または変更がない場合は確認せず閉じる
- 入力エラーが複数ある場合は、最初のエラー項目へスクロールしてフォーカスする。保存中は終了と重複送信を抑止する

#### 画像処理と保存順序

- フロントエンドは選択画像を縦横最大400px、品質0.5のJPEG Blobへ変換し、変換後Blobが3MB以下であることを確認する
- バックエンドは申告MIMEだけでなくPNG／JPEG署名、実形式、デコード可否、縦横、展開後40,000,000画素以下を検査し、メタデータを引き継がず再エンコードする
- 画像なしの作成はルーム作成APIだけを呼ぶ。画像ありの作成はルーム作成、画像アップロード、返された画像名によるルーム更新の順に呼ぶ
- 画像を変更する編集は、画像アップロード後にルーム更新を行う。DB更新後に以前の画像を削除する
- 保存済み画像と選択中画像の分離、取消・削除、同じファイルの再選択、保存失敗時の状態は[保存済み画像の差し替えと取消](../media-input.md#保存済み画像の差し替えと取消)に従う
- ルームでは新画像のプレビュー中に画像選択ボタンも隠す。新規作成時の選択取消は画像なしへ戻す
- 作成成功時は返されたルームを一覧先頭へ追加し、編集成功時は対象要素を置換する

#### 保存後の処理

- 作成時にルームと翻訳を保存し、所属フロアのフロアタグをルームタグへ、フロア単語のグループ・項目をルーム単語へコピーする
- ルーム用メディアディレクトリを作成する
- ルーム作成・設定変更・削除はSocket.IOのルーム更新イベントを送信しない

### 並び替え・公開状態・削除

#### 並び替え

- 並び替えはドラッグ操作だけで、キーボードから順序を変更する代替操作がない

- `vuedraggable`のハンドルをドラッグして一覧配列を並び替える
- 実際に位置が変化した場合だけ、一覧内の全ルームについて0始まりの`display_order`を送る
- バックエンドは同じフロアに属するアクティブなルームだけを更新し、対象外IDは無視する
- 成功時はstatusのスナックバーを表示する。401以外の失敗時は画面上の順序を直前の状態へ戻す

#### 表示状態の一括変更

- `floor_id`と`room_display_hidden`を送信し、対象フロアの全アクティブルームを表示または非表示へ変更する
- 成功後はルーム一覧を再取得する
- `room_display_hidden`の変更は一覧表示へ影響するが、ルーム入室の認可条件は変更しない

#### 削除

- 「ルームを削除」確認では「対象ルーム」にルームカードと同じ翻訳済み表示名を示し、通常操作では対象ルームとタイムラインを利用できなくなることを説明する。初期フォーカスは「キャンセル」とし、確定操作だけを危険操作として表示する
- 確認ダイアログを経てルームを論理削除し、成功後に現在の一覧から対象を除去する
- ルーム削除は配下の投稿、ルームタグ、ルーム単語、ルームAI解析設定、メディアを連鎖削除しない。有効なAI解析設定が存在しても削除できるが、通常の一覧・タイムラインAPIと解析実行では削除済みルームを起点に利用できなくなる。ルーム復元後は有効な設定を既存状態のまま再び利用できる

### フロア／ルーム関連管理

- フロア／ルームタグは一覧ダイアログ内で作成・編集画面へ切り替え、削除時だけ親一覧を維持した確認ダイアログを重ねる。フロアタグは一覧、入力、削除確認に同じ対象フロア名を、ルームタグは同じ対象ルーム名を示す。どちらも読込中、正常一覧、0件、取得失敗と再試行を区別する。「共通タグに戻す」「フロアタグに戻す」は、同期元にないタグが一覧から外れることを確認してから実行する
- フロア／ルームAI解析設定はAdministratorとFloorEditorだけに表示し、タグ操作の隣から有効設定のダイアログを開く。同じダイアログ内で一覧と作成・編集画面を切り替え、一覧の主要操作は「作成」と表示する。削除だけは親一覧を維持した確認ダイアログを表示する。フロア設定は同じ対象フロア名、ルーム設定は同じ対象ルーム名を一覧、入力、削除確認で維持する。削除済み設定は一覧へ戻さず復元操作を提供しない。両ロールが「付加情報を行うユーザ」を明示検索・指定し、親設定から独立して管理する。詳細は[AI解析設定管理画面](AIAnalysisSettingManagement.md#フロアルーム設定ダイアログ)を参照する
- フロア／ルーム単語はルーム一覧の対象ボタンから管理ダイアログを開き、ルーム一覧のURLとスクロール位置を維持する。PCは広幅、スマートフォンは画面内をほぼ満たすダイアログとし、一覧とグループ／単語の作成・編集を同じダイアログ内で切り替える。フロア単語では「対象フロア」、ルーム単語では「対象ルーム」を一覧、入力、削除確認で維持し、削除時は各対象名と削除対象を示す確認ダイアログを親一覧へ重ねる。未保存の入力を終了する場合も、変更の破棄を確認する
- フロア／ルームの作成済み招待URLは、画面幅に合わせて折り返し、全文に合わせて高さが広がる読取専用欄に表示する。「コピー」は表示上の折り返しを含めず、元のURLをコピーする。本文が長い場合は本文だけをスクロールし、閉じる・コピーは共通の操作領域に残す
- フロアメンバー招待は対象フロアと一覧と同じ権限説明を示し、有効期限の選択と招待URL作成を同じ行に配置する。発行後に有効期限を変更した場合は、表示中URLをコピーできない状態にして再発行を案内する
- フロアメンバー一覧は対象フロア、フロアメンバーが利用できる主な操作と利用できない管理操作、件数を示し、権限説明をダイアログの説明参照へ含める。読込中、正常一覧、0人、取得失敗と再試行を区別する。管理権限がある利用者だけがメンバーを削除でき、削除確認中も親一覧を維持する。削除成功後は次のメンバー、前のメンバー、一覧見出しの順でフォーカスを移す
- フロアメンバー本人の脱退確認は対象フロアを示し、脱退成功後にフロアへ戻る
- メンバー限定ルームのカードからルームメンバー招待URLの発行とルームメンバー一覧を開く。両ダイアログは対象ルームと同じ権限説明を示す。招待ダイアログは有効期限の選択と招待URL作成を同じ行に配置する。招待URLは作成完了を通知するラベル付き読取専用の複数行欄へ表示し、発行後に有効期限を変えた場合は再作成が必要であることを案内する
- ルームメンバー一覧はルームメンバーが利用できる主な操作と利用できない管理操作を示し、権限説明をダイアログの説明参照へ含める。読込中、正常一覧、0人、取得失敗と再試行を区別する。一覧から削除確認へ進む間も親一覧を維持し、削除成功後は次のメンバー、前のメンバー、一覧見出しの順でフォーカスを移す
- キック済みユーザ一覧は対象フロアと件数を示し、読込中、正常一覧、0人、取得失敗と再試行を区別する。行操作は削除ではなく「解除」とし、解除確認では親一覧を維持して対象フロアと対象ユーザを示す。この画面から新規キックは行わない

## 通信・エラー時の動作

- 作成・画像アップロード・画像名更新は別APIであり、途中失敗時に作成済みルームまたは未参照画像が残る
- DB更新後の旧画像ファイルの削除に失敗しても更新は成功し、ファイルが残る場合がある

### 使用するAPI

| 用途 | Method / Path | 認証・主な条件 |
| --- | --- | --- |
| フロアロール取得 | `POST /api/floor/role` | JWT必須 |
| キック状態確認 | `POST /api/kickeduser/check` | JWT必須 |
| フロア詳細取得 | `POST /api/floor/detail` | JWT不要、アクティブなフロア |
| ゲスト向けルーム一覧 | `POST /api/room/guest` | JWT不要。非表示でない有効なルームを取得する（メンバー限定ルームも含む） |
| ログイン向けルーム一覧 | `POST /api/room` | JWT必須、フロアロールで非表示ルームの範囲を決定し、各ルームへ現在ユーザのルームメンバー所属状態を付加 |
| 入室ロール取得 | `POST /api/chat/role` | JWT必須 |
| ルーム作成 | `POST /api/room/create` | Administrator／FloorEditor／フロアメンバー |
| ルーム更新 | `POST /api/room/update` | Administrator／FloorEditor／フロアメンバー |
| ルーム削除 | `POST /api/room/delete` | Administrator／FloorEditor／フロアメンバー |
| 表示順更新 | `POST /api/room/update/displayorder` | Administrator／FloorEditor／フロアメンバー |
| 表示状態の一括変更 | `POST /api/room/update/roomdisplayhidden` | Administrator／FloorEditor／フロアメンバー |
| ルーム画像アップロード | `POST /api/fileupload/room/image` | 対象ルームを管理できる利用者 |
| フロア／ルームAI解析設定 | `/api/flooraianalysissetting`、`/api/roomaianalysissetting`配下 | Administrator／FloorEditor |
| ルームメンバー招待 | `POST /api/roommember/invite` | Administrator／FloorEditor／フロアメンバー、メンバー限定ルームのカードから実行 |
| ルームメンバー一覧 | `POST /api/roommember` | Administrator／FloorEditor／フロアメンバー／対象ルームメンバー、メンバー限定ルームのカードから実行 |

- タグ、AI解析設定、単語、フロアメンバー、ルームメンバー、KickedUserのAPI契約は関連仕様を参照する

### Socket.IOとの関係

- ルーム画面自身はSocket.IOへ接続せず、ルームの作成・更新・削除や表示順変更を画面へ反映するイベントも送受信しない
- タイムラインへ遷移した後に、接続時点のフロア／ルーム／ユーザ状態とロールを使ってSocket.IOの購読可否を判定する
- KickedUserの新規登録処理は`KICKED_USER`を対象ユーザへ送信し、対象フロアのSocket.IO接続を切断する。ルーム画面で行うキック解除は既存接続を自動再接続しない

### 読み込み中・データなし・エラー時

- ルーム一覧取得、公開状態変更、並び替え中は`sending=true`とし、重複処理とドラッグを抑止する
- 一覧が0件の場合はルームを表示しない。専用の空状態メッセージや再読込ボタンはない
- 初期化失敗はフロア遷移後にフロア画面のスナックバーで通知する
- 入室拒否と画面内管理操作の失敗は、現在画面のalertスナックバーで通知する
- 認証エラーの401は共通認証エラー処理によりログアウトしログイン画面へ遷移する。`INVALID_PERMISSION`ではログアウトしない
- フロア／ルームタグ、フロア／ルームAI解析設定、フロア／ルーム単語、フロア／ルームメンバー、キック済みユーザの一覧ダイアログは、読込中、正常一覧、取得成功後の0件、取得失敗を別の状態として表示し、取得失敗時はインラインの再試行を提供する
- 一覧のGET中はダイアログを閉じられる。終了後または別対象へ切り替えた後に到着した古い応答は表示へ反映しない。各ダイアログの送信・変更処理中は終了と重複操作を抑止する。ただし、フロア／ルームAI解析設定の結果ユーザ検索は変更送信とは別状態であり、検索中も戻る、Escape、背景クリックを抑止しない
