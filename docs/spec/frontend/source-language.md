# 本文言語の訂正と文字起こし翻訳

## 目的と操作

画面の表示言語と本文に使われている言語を分ける。投稿・返信・付加情報の作成／編集画面に「本文の言語」を表示する。新規作成時の初期値は画面の言語、編集時は保存済みの本文言語である。言語だけを訂正して保存でき、画面の表示言語は変えない。連続投稿で入力欄を空にした際も、その場で選んだ本文言語を引き継ぐ。

1. 編集できる投稿や返信の編集画面を開く。
2. 「本文の言語」を実際の本文の言語へ変更して保存する。
3. 古い翻訳を削除し、フロア設定・接続中ユーザーなど既存の翻訳先規則で作り直す。

編集権限は既存のまま。ゲストに既存投稿の編集権限を新設しない。ゲストの投稿言語訂正は、権限を持つ管理者等へ依頼する。新規ゲスト投稿でも本文言語を選択できる。AIの付加情報は、共同編集を許可したルームのログインユーザー、または従来の編集権限を持つ人が本文と言語を訂正できる。

## 保存と競合

既存の `lang` と `translations` を使用し、DBスキーマや役割は追加しない。言語のみの訂正でも解析元の版番号は進め、古い入力に基づく処理の保存を防ぐ。ただし、言語だけの訂正でAI解析を再実行しない。既に保存されたAI付加情報は保持する。本文・媒体・タグを変更した場合は既存の再解析規則を使う。

本文または言語の変更時は、翻訳機能が停止中でも古い翻訳を消す。翻訳の保存は本文・原文言語・未削除状態が開始時と一致する場合に限る。投稿、返信、その付加情報、ゲスト作成時の翻訳にも同じ条件を使う。翻訳不能時は原文を保持し、誤った旧訳に戻さない。

## AI文字起こし

画面や投稿の言語を、録音の発話言語としてOpenAIへ強制指定しない。文字起こしAPIの言語自動判定を使い、文字起こし本文をGoogle翻訳へ原文言語未指定で渡す。Googleの各翻訳応答の `detectedLanguageCode` が対応言語の同じ値で一致した場合、その言語を付加情報の `lang` へ保存する。

翻訳先はフロアの対象言語と投稿言語の和集合。投稿言語も含めるのは、発話言語と異なる場合に翻訳を欠落させないため。原文と同じ言語の翻訳は保存時に除外する。タグの接頭辞を除いた文字起こし本文を翻訳・判定に用い、表示用接頭辞は翻訳先ごとに付ける。

言語判定が得られない、未対応言語である、判定が一致しない、翻訳が無効または失敗した場合、原文は保存し、言語は `null`（不明）とする。投稿言語からは推測しない。これは既存のnullable欄の使い方の変更であり、新しい構造の追加ではない。手動編集では言語を選んでから保存する。短い発話や混在言語での自動判定精度は保証しない。

モデル・資格情報・音解析経路は変更しない。過去の投稿は一括変換しない。誤った言語で保存済みの文字起こしは、本文編集から言語を訂正して翻訳を作り直す。元の録音を再送する必要はない。発話未検出の固定案内は従来の日英表示を保持する。

Google公式仕様: [translateText](https://docs.cloud.google.com/translate/docs/reference/rest/v3/projects/translateText)（原文言語省略時の自動判定）。

## 検証

`backend/tests/integration/services/sourceLanguageCorrection.int.test.js` は実DBで言語のみの訂正、権限、保存済みAI情報の保持、遅延翻訳の破棄を検証する。外部APIは固定応答であり、実APIの認識・翻訳精度試験と区別する。

UIのネイティブselectにはラベルと説明文を関連付ける。日英の名前・選択状態・キーボード操作を確認対象とし、VoiceOverの実音声確認とは区別する。
