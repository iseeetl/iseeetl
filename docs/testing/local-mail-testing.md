# ローカル開発環境でのメール手動確認

ローカル開発環境から送信したメールをMailpitで捕捉し、画面で確認する手順です。外部SMTPや実在する宛先は使用しません。

## 前提

- フロントエンドへ`http://localhost:3000`でアクセスできる
- バックエンドとMongoDBが起動している
- Mailpitの画面へ`http://localhost:8025`でアクセスできる
- バックエンドからMailpitのSMTPポート1025へ接続できる
- Mailpitに外部SMTPリレーや転送先が設定されていない

同じサーバで動かす場合はバックエンドから`127.0.0.1:1025`へ接続します。ComposeではバックエンドとMailpitを同じネットワークに置き、`mailpit:1025`へ接続します。画面用の8025番ポートをホストへ公開する場合はループバックに限定し、SMTPの1025番ポートは公開しません。

開発環境は[ローカル開発の準備](local-development.md)、Mailpitの導入・起動は[テスト用サービスの準備](service-setup.md#mailpit)を参照してください。フロントエンド・バックエンドは通常開発用の3000／5000を使用します。

## バックエンドのメール設定

バックエンドの開発用設定で、次の変数を確認します。実在するメールアドレスや外部SMTPは使用しません。

| 変数 | ローカル確認で使用する値 | 用途 |
| --- | --- | --- |
| `EXTERNAL_MAIL_DELIVERY_ENABLED` | `true` | メール機能を有効にする |
| `SEND_MAIL_HOST` | 同じサーバでは`127.0.0.1`、Composeでは`mailpit` | Mailpitの接続先 |
| `SEND_MAIL_PORT` | `1025` | MailpitのSMTPポート |
| `NO_REPLY_MAIL` | `local-noreply@example.invalid`など | 送信元 |
| `VUE_APP_APPNAME` | ローカル用のアプリ名 | 送信者名、件名、本文に使用する |
| `VUE_APP_APPURL` | `http://localhost:3000` | 有効化・再設定リンクの生成元。末尾に`/`を付けない |

設定値の前後に余分な空白を含めないでください。

`VUE_APP_APPURL`はバックエンド全体の起動時必須設定でもあります。

設定を変更した場合はバックエンドを再起動します。変数の検証条件は[バックエンド環境変数](../spec/backend/environment-variables.md#メール送信)を参照してください。

## ユーザ登録メールを確認する

1. Mailpitを他の手動確認やE2Eが使用していないことを確認してから画面を開く。
2. `http://localhost:3000`を開き、ログイン画面から「ユーザ登録へ」を選ぶ。
3. 毎回異なる架空のメールアドレスを入力する。例: `manual-<一意な値>@example.invalid`
4. 必須項目と同意欄を入力し、「OK」を押す。
5. 「ユーザ仮登録完了」が表示されることを確認する。
6. Mailpitに有効化メールが1件届き、宛先、件名、本文、リンク先が想定どおりであることを確認する。
7. メール内の有効化リンクを開き、有効化成功画面が表示されることを確認する。
8. 登録したメールアドレスとパスワードでログインできることを確認する。

`example.invalid`は実メールの送信先として使用しない予約済みドメインです。Mailpitで受信するため、実在するアドレスは必要ありません。同じアドレスは再利用せず、確認ごとに一意な値を使用します。

画面操作の詳細は[ユーザ登録](../manual/features/register.md)と[ユーザ本登録](../manual/features/user-activate.md)を参照してください。

## パスワード再設定メールを確認する

1. 前節で有効化したユーザを用意する。
2. ログイン画面からパスワード再設定を要求する。
3. Mailpitに再設定メールが届き、リンクが`http://localhost:3000`から始まることを確認する。
4. メール内のリンクから新しいパスワードを設定する。
5. 完了通知メールが届き、新しいパスワードでログインできることを確認する。

画面操作の詳細は[パスワード再設定](../manual/features/password-reset.md)を参照してください。

## 確認できるメール種別

現行実装では、次のメールを共通の多言語生成処理で生成します。HTMLテンプレートファイルへ分離されておらず、文言とHTML組み立ては`backend/services/mail/localizedMail.js`にあります。

- ユーザ仮登録と有効化URL
- パスワード再設定URL
- パスワード再設定完了通知
- ログイン中のパスワード変更通知

SMTP接続処理は`backend/integrations/mail/mailer.js`にあります。

## 届かない場合

- ユーザ登録への導線が表示されない場合は、メール機能が有効になっているか確認する。
- バックエンド起動時に設定エラーになる場合は、必須変数の不足、ポートの形式、送信元アドレスの形式、フロントエンドURLの形式を確認する。
- 登録操作でメール送信エラーになる、またはMailpitにメールがない場合は、バックエンドから設定したMailpitの接続先と1025番ポートへ接続できるか確認する。
- メール内リンクが別のオリジンを指す、またはパスの前が`//`になる場合は、`VUE_APP_APPURL`の値と末尾の`/`を確認してバックエンドを再起動する。
- 登録済みと表示される場合は、別の一意な`example.invalid`アドレスでやり直す。

仮ユーザ作成後にSMTP送信が失敗した場合、APIは失敗を返しますが、作成済みの仮登録データが残ることがあります。SMTPを直した後も同じアドレスの状態を推測せず、手動確認では新しい一意なアドレスを使用してください。この手順では再送や仮登録データの手動削除は行いません。

メール本文には有効化・再設定用トークンが含まれます。Mailpitの画面や本文を共有資料へ転載せず、確認後は今回使用した一意な宛先のメールだけを削除してください。

有効化した試験ユーザと送信失敗時の仮登録データは、この手順では手動削除しません。継続利用するローカルDBでは一意な`example.invalid`アドレスで試験データと識別し、DBの初期化が必要な場合は、対象DBと保存が必要なデータを環境管理者に確認してください。
