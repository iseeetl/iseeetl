# フロントエンドリリース品質確認

フロントエンドのリリース候補について、自動テスト、ビルド、成果物、E2E、変更画面の手動確認を行うチェックリストです。

## 前提

- テスト・ステージング環境で、同じバージョンまたはリビジョンを対象に確認します。本番環境への配置・切替は扱いません。
- ブラウザ・OS・端末の対応範囲、性能、アクセシビリティは[非機能要件](../spec/non-functional-requirements.md)、成果物の構成は[リリース成果物仕様](../spec/release-artifact.md)を参照します。このチェックリストだけで全要件への適合を判定しません。
- 依存パッケージは[テスト環境の共通準備](test-environment.md#共通準備)に従って導入します。

## 事前確認

1. リリース対象のバージョンまたはリビジョンを固定します。
2. フロントエンド、バックエンド、公開設定、E2E DB、リリース成果物が同じリリース候補に対応していることを確認します。
3. 使用するNode.js、npm、ブラウザ、バックエンドのバージョンを確認します。
4. リリースで有効にする外部サービスが、次の確認範囲に収まることを確認します。

標準E2Eで確認する外部連携は、Mailpitによるメールと、ローカルCDPモックによるAnalyticsのフロントエンド契約です。OneSignal、LINE、Googleログイン、Google Translate、実際のGA4プロパティなどへの接続・送信は、このチェックリストでは確認しません。有効にする場合は、対象サービスの検証も別途行ってからリリースを判断します。

## 自動確認

### フロントエンドの単体テスト、lint、ビルド

以下はリポジトリルートから実行します。

```bash
set -eu
npm --prefix frontend run test:unit:ci
npm --prefix frontend run lint
npm --prefix frontend run test:build
```

`test:build`では開発・ステージング・本番環境向けの各ビルドとマニフェストを確認します。コマンドの詳細と失敗時の確認は[テスト環境の準備とコマンド選択](test-environment.md)を参照してください。

### リリース成果物の確認

検証対象の配布パッケージがある場合は、[リリース成果物仕様](../spec/release-artifact.md)と照合して次を確認します。

- マニフェストと必須アセットが揃っている。
- リリースIDとチェックサムが対象バージョンに対応している。
- 秘密値、E2E専用設定、テスト用ソース、不要なファイルが成果物へ含まれていない。

### フロントエンドE2E

[フロントエンドE2Eテスト実行](e2e-testing.md)に従い、隔離環境で`core`プロファイルを実行します。`mail`または`analytics`をリリースで使用する場合は、対応するプロファイルも実行します。固定アカウントを変更するテストは、各テストの直前に専用DBを初期化して一つずつ実行します。

前提不足によるスキップは成功として扱いません。

## 手動確認

変更内容に応じて、次を対象ブラウザで確認します。

1. 変更した画面と、その画面へ至る主要導線。
2. レイアウトへ影響する変更では、デスクトップとモバイルの代表表示領域。
3. キーボード、フォーカス、アクセシビリティ名、色以外の状態表示へ影響する変更では、該当する操作。
4. PWA、マニフェスト、ショートカットへ影響する変更では、生成されたマニフェスト、通常・フロア・ルームの各ショートカットの起動、iOS再読込み時の動作。iOSホーム画面アプリの画像共有を変更した場合は、iPhone実機で共有画面を閉じてアプリへ戻れることも確認する。
5. ブラウザまたは端末固有の変更では、その変更が対象とする環境。

性能へ影響する変更を比較する場合は、直前リリースと同じ測定条件を使い、条件と結果を記録します。定義されていない数値を合格閾値として使用しません。

## 成功判定

次のすべてを満たした場合にフロントエンドの品質確認が成功です。

- 必須として選択した単体テスト、lint、ビルド、リリース成果物検査、E2Eが成功している。
- 必須シナリオを環境不足や前提不足でスキップしていない。
- 本番用成果物に秘密値、E2E専用設定、テスト用ソース、未置換のプレースホルダー、不要な公開ディレクトリが含まれていない。
- 変更した主要導線と、変更に対応する表示領域、キーボード等の手動確認が完了している。
- 事前確認の前提が維持されている。
- 対象バージョンまたはリビジョン、実行環境、コマンド、成功、失敗、スキップ、未実施項目を記録している。

## 中止条件

事前確認または成功判定の条件を満たさない場合は、リリース作業へ進みません。必須テストの失敗・スキップや、本番用成果物への秘密値・テスト専用設定の混入がある場合も中止します。
